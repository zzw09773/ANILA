# Gate 6 P0 production acceptance profile

`production-acceptance-profile.disabled-template.json` is an authoring
template only.  Its explicit `enabled: false`, `template_only: true`, and
`approval_status: "disabled_template"` state are evidence that no production
approval exists.  It intentionally contains no thresholds, topology, evidence,
hash, or signature.  The runtime verifier rejects this file by default.

## Profile contract

The machine-readable contract is
`anila.gate6.production-acceptance.v1`, implemented in
`packages/anila-security/src/anila_security/production_acceptance_profile.py`.
Every root and nested field is exact-set validated.  A real profile must be
completed by the responsible owners; this repository does not choose actual
RTO/RPO, SLO, load, observation, classification, or revocation values.

The required P0 fields are:

- production topology and artifact hashes;
- enabled/disabled features and classification ceiling;
- RTO/RPO, SLO thresholds, load profile, observation window, workflow matrix,
  and fixed P5 sample `N`;
- enabled inference callsite inventory schema/version/hash and callsite IDs;
- token/card revocation SLA and a PKI stale/offline/missing fail-closed policy;
- Sev-1/Sev-2 taxonomy, finding acceptance rule (Critical/High reject and
  auth/classification/egress bypasses blocked; any conditional acceptance
  requires owner, expiry, compensating control, and independent signoff), and
  revalidation impact matrix version/hash;
- the five signer roles: `system_owner`, `data_owner`, `pki_owner`, `security`,
  and `operations`.

## Verification rules

Use an out-of-band trust store with exactly one distinct Ed25519 public key
for each required role.  Signatures are base64 Ed25519 signatures over the
canonical UTF-8 JSON payload with the `signatures` member removed.  The
`profile_content_sha256` is SHA-256 over canonical JSON with both
`profile_content_sha256` and `signatures` removed.  The verifier checks the
profile hash first, then every signature, profile validity window, and all P0
constraints.  Unsigned, disabled, stale, tampered, or partially signed
profiles fail closed.

Example (after an owner has completed and separately signed a profile):

```python
from anila_security.production_acceptance_profile import (
    verify_signed_production_acceptance_profile,
)

verified = verify_signed_production_acceptance_profile(
    "production-acceptance-profile.json",
    "production-acceptance-trust-store.json",
    inventory_path="enabled-inference-inventory.json",
)
```

No key, signature, or production approval is generated by this repository.

The observation window is a hard P3 prerequisite: both the declared minimum
and the actual `start` to `end` interval must cover at least seven consecutive
days, and the complete window must be contained by `valid_from`/`valid_until`.
The verifier does not require the window to have elapsed yet, so owners can
sign the profile before the observation run begins.
