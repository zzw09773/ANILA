## 待修（四條）

### 🔴 F-1 「註冊」表單送出後顯示英文的 `Not Found`

**重現**：登入頁 →「其他登入方式」→「註冊」→ 填帳號/EMAIL/密碼 →「送出」
**使用者看到**：`! Not Found`（英文，未翻譯）
**根因**：前端 `apps/csp-governance-ui/src/api/auth.js:21` 打 `POST /api/auth/register` → 實測 **404**
**驗證**：curl 與 UI 各試一次，`users` 表**零新增**——安全面沒問題，後端 `register()`
第一行就是 `_reject_when_card_only()`。

⚠ **為什麼排第一**：這是**三千人看到的第一個畫面**。那顆按鈕開出一個做得很完整的表單
（含即時的「8 字元以上·大寫·小寫·符號」強度指示），填完得到一句英文 `Not Found`。
使用者不會知道那是「這個部署模式不開放自助註冊」。

### 🟡 F-2 card-only 下整塊「其他登入方式」對一般使用者都是死路

帳密登入在 `ANILA_AUTH_MODE=card-only` 時**只保留給 owner**
（`services/csp/app/api/auth/password.py:88-93`）。一般同仁填了帳密按登入，**必定失敗**。
👉 建議 card-only 時整塊隱藏，或改成一句「本平台僅接受憑證卡登入」。owner 破窗留著。

### 🔴 F-3 首次上線硬阻擋：沒有單位，任何人都完不成註冊

卡登驗章通過後，畫面要求選單位，但「**目前沒有可選的單位，需要管理員先建立。**」
DB 實測 `departments` **0 筆** → **提示是誠實的**（不是假控制項 ✅）。
⚠ **但三千人插卡都會卡在這一步**，而第 8 段演練是 `down -v`，單位會歸零 → **演練必撞**。
👉 「建立單位」必須列進部署文件的初裝必要步驟（與 admin 密碼最後一哩、JWT keypair 並列）。
📌 平台已知這個家族的風險：`startup_security.py:68-72` 擋了
`CARD_INITIAL_OWNERS` placeholder 導致「沒人能 approve → bricked」，**但「零單位」沒有對應守衛**。

### 🟡 F-4 打錯網址 → 完全空白的頁面（治理中心沒有 catch-all 路由）

實測不存在的路徑 → `innerText` 長度 **0**，沒有「找不到頁面」、沒有回首頁的路。
⚠ **我自己就被這個騙過**：第一輪我掃了三個**我編的路徑**，全部「零錯誤、零按鈕」，
差點報成「頁面壞掉」。**空白頁不產生錯誤，所以它能通過任何以「有沒有錯誤」為判準的檢查。**

### 🟡 F-5 「重新載入 agent」按了沒有任何回饋

實測：**確實發出** `/v1/agents` 請求，但畫面完全沒變化——沒有轉圈、沒有「已更新」。
使用者無法分辨「按了有用」與「按了沒用」。⚠ `docs/FAKE-CONTROLS.md` 那一族的輕症版本。
