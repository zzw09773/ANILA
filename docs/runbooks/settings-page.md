# Runbook — 從畫面改設定（治理中心「平台設定」）

> 對象：平台管理員（admin 以上）。單顆設定約 1 分鐘，需要重啟的那類再加一次重開。
> 背景：這一頁之前，csp 的每一顆環境變數都只能改 `.env` ＋ recreate（運維動作，
> 氣隙內要重新交付才改得動）。現在 **96 顆設定全部上頁**——包含 57 顆從來沒出現在
> compose、只吃程式預設值的隱形變數——其中一部分可以直接從畫面改。
> ⚠ **這一頁不是「什麼都能改」**：能不能改、改完什麼時候生效，逐顆是硬規則，寫在頁面上。

## 在哪裡

治理中心 → 側邊欄 **「平台設定」**（路徑 `/platform-settings`）。**admin 限定**（讀寫同一道門）。

## 四個區，各自的承諾不一樣

頁面依「改完會發生什麼」分四區。**區的標題就是那一區的承諾**，不要跨區推論：

| 區 | 存檔之後 | 你要做的事 |
|---|---|---|
| **改完立刻生效** | 下一個請求就是新值（每次請求都重新查 DB，沒有快取） | 沒有了。存完就結束 |
| **改得動，但要重啟才生效** | 值進 DB，**下一次開機**才會蓋過 env | 讓 csp 重開一次（見下節） |
| **這裡改不動** | — | 看那一列的**鎖定理由**，它會告訴你真的要改的話去哪裡改 |
| **祕密：只說設了沒有** | — | 值永遠不會離開後端。要換就是換 `.env`／secret 再重新部署 |

每一列都有 **「來源」欄**（DB／env／程式預設）——**值沒生效的時候先看這一欄**，
不要先去翻 compose。來源說 `env`，就表示 DB 那一層沒有東西在贏；來源說 `db-boot`，
就表示現在跑的是這次開機從 DB 載進來的值。

## 「要重啟才生效」的那一區：存完之後

1. 存檔。頁面會回一句 **`已儲存，重啟後生效：docker compose up -d csp`**，
   而且那一列會**同時**顯示「現在生效」與「待生效（重啟後）」兩個值——
   兩個值不一樣是正常的，那就是這一區的全部意思。
2. 讓 csp 重開一次：

   ```bash
   docker compose -p <專案名> up -d csp     # 本機重啟樹是 -p anila-restart
   ```

3. **回頭看那一列**（這一步不能省）：重開之後「現在生效」必須變成你存的值，
   來源變成 `db-boot`。
   ⚠ **如果它還是舊值，代表容器根本沒有被重開。** `up -d` 是拿 compose／`.env`
   算出來的設定去比對容器，比對相同時它會判定「已是最新」而不動它——而你這次改的
   東西只在 DB 裡，compose 沒有任何變化。真的沒重開就用：

   ```bash
   docker compose -p <專案名> up -d --force-recreate csp
   ```

   👉 順帶：**改 compose／`.env` 的時候一律 `up -d`，不要 `docker restart`**
   （原因見 [`restart-vs-recreate.md`](./restart-vs-recreate.md)）。

4. 頁面最上面如果出現紅字 **「這次開機沒有載入設定覆蓋」**，
   代表這一次開機**一顆覆蓋都沒有套上去**，現在跑的是 env／compose 或程式預設。
   標著「重啟後生效」的承諾這一輪全部落空——banner 上會寫原因，先解決它再談設定。
   （這是刻意的 fail-soft：載入失敗時服務照樣以 env 值開機，但**絕不假裝覆蓋生效了**。）

## 「這裡改不動」的那一區：真的要改的時候

**每一列的鎖定理由就是那一列的操作指南**——它寫著為什麼鎖著，降級鎖起來的那幾顆
還把**要改哪一個 compose 鍵**寫在句尾。照那一句做：改 compose／`.env` 的那個鍵 →
`docker compose -p <專案名> up -d csp` → 回頭看那一列的「現在生效」與「來源」。

⚠ **這份 runbook 刻意不抄一份「哪一顆對應哪個鍵」的清單。** 對應關係跟著登錄表
（`services/csp/app/services/settings_registry.py`）走，抄第二份就會漂掉，
而漂掉的那一份不會有人發現——那正是這一頁存在要消滅的東西。

## 值域：填不進去不是壞掉

每一顆都有宣告的值域，超出範圍會被 **400 擋下並且不留任何一列**，
錯誤訊息會把合法區間講出來。**擋下來是設計**：值域是防呆生命線，
「從畫面把平台打掛」必須是不可能的，不是「不建議」。

如果你覺得某顆的下界擋得莫名其妙，先讀那一顆的說明——例如告警輪詢週期的下界是 15 秒，
因為**消費端本來就有一個 15 秒的硬樓地板**：填 7 不會讓偵測變密，只會被靜默提到 15。
與其收下一個平台不會照辦的值，不如當場不收。

## 存了但沒生效的三種樣子（照這個順序查）

1. **「待生效」還亮著** → 還沒重開，或重開的指令沒有真的 recreate 容器（見上面第 3 步）。
2. **那一列寫「存了但讀不回來，永遠不會生效」** → DB 裡那一列的字串現在解不出合法值
   （多半是舊值撞上後來收緊的值域）。重存一次就好，**壞掉的列不會被拿來用**。
3. **來源欄說 `env`，而你以為 DB 該贏** → 那一顆屬於「改不動」的區，或是這次開機
   沒有載入覆蓋（看最上面的 banner）。

## 這一頁不管的事

- **其他服務**（router／ingestion-worker／asr）的設定：這一頁只有 **csp 行程讀得到**的東西。
  OCR 那一組的主要消費者是 ingestion-worker（另一個行程，讀不到 csp 的 DB），所以它們鎖著。
- **純 compose 插值**的變數（不進容器 env 的那幾顆）不在頁上。
- **零讀取點的死變數永遠不會出現在這一頁**——頁面上看得到的每一顆，都真的有人讀。
