# Phase 6 — E2E 驗收 runbook

**目標**:在 PR #12 merge 進 main 之前,**user 必須親手**從 browser 跑完整 deck 生成流程,確認 anila-studio 抽出後沒漏接邏輯。

通過後 Phase 7 的 csp 端刪檔才算「斷尾」成功;失敗就 revert PR #12 回到合 PR 前的狀態。

## 前置(deploy)

1. **pull feature branch**:
   ```bash
   git fetch origin feature/anila-studio-extract
   git checkout feature/anila-studio-extract
   ```

2. **csp / anila-studio 要新環境變數**:csp 已切 RS256,要先生 JWT key pair:
   ```bash
   cd myCSPPlatform/backend
   .venv/bin/python scripts/generate-jwt-keypair.py
   ls -la secrets/jwt-private.pem secrets/jwt-public.pem
   ```
   
   private key 權限 `0o600`,**不能 commit**(`.gitignore` 已 ignore)。

3. **rebuild 整 stack**(dev):
   ```bash
   docker compose -f docker-compose-dev.yml down
   docker compose -f docker-compose-dev.yml up -d --build csp anila-studio anilalm
   docker compose -f docker-compose-dev.yml ps
   ```
   
   檢查 5 個 service healthy:
   - `anila-platform-dev-csp-1` (healthy)
   - `anila-platform-dev-anila-studio-1` (healthy)
   - `anila-platform-dev-anilalm-1` (healthy)
   - `anila-platform-dev-pptx-renderer-1` (healthy)
   - `anila-platform-dev-redis-1` (healthy)

4. **smoke check**:
   ```bash
   # csp 自身 health
   curl -sf https://localhost:9443/api/health || curl -sf http://localhost:8000/health
   
   # anila-studio health(透過 anila-studio 容器或 nginx route)
   docker exec anila-platform-dev-anila-studio-1 curl -sf http://localhost:8100/health
   # 期望:{"status":"ok",...,"ready":true,"deps":{"revocation_cache":true}}
   
   # JWKS
   docker exec anila-platform-dev-anila-studio-1 curl -sf http://csp:8000/.well-known/jwks.json
   # 期望:{"keys":[{"kty":"RSA","alg":"RS256","kid":"anila-v1",...}]}
   ```

5. **預期 cutover 副作用**:
   - 所有 user **必須重登一次**(HS256 → RS256)
   - 重登後 access token 帶 `kid: anila-v1` header

## E2E 步驟(從 browser)

1. **Login**:
   - 進 https://localhost:9443/(或 ANILALM 入口)
   - admin 帳號重登(密碼從 .env 拿,或既有 admin)
   - DevTools → Network 觀察 `/api/auth/login` 200,response 包含 `access_token`
   - 在 Application → Cookies 看到 `anila_access_token`

2. **Studio 入口**:
   - 點 ANILALM 左側「鑄造投影片」/ Studio entry
   - 應該看到 Studio Wizard(主題選擇)

3. **選 collection**:
   - 挑一個既有 ingestion collection(有 PDF + image 的)
   - 沒 collection 的話先 upload 一份 PDF 到 csp 的 ingestion

4. **生成 deck**:
   - 在 Studio Wizard 點「生成投影片」/ 觸發 job
   - DevTools Network 應看到:
     - **POST `/api/studio/slides/jobs` → 202**(回 `job_id`)
     - 這條 request **的目標是 `localhost:8100`**(或 nginx route 到 anila-studio),**不是 csp:8000**
     - polling `GET /api/studio/slides/jobs/{job_id}` → 200 with `state: "running"`...

5. **觀察 anila-studio 跟 csp 的協作**(`docker logs` 旁觀):
   ```bash
   docker logs anila-platform-dev-anila-studio-1 -f --tail 50
   ```
   
   應該看到 anila-studio 打 csp:
   - `GET /api/ingestion/collections/{id}` (collection 中介資料)
   - `POST /api/ingestion/collections/{id}/search` (RAG chunks)
   - `POST /api/ingestion/collections/{id}/images/search` (RAG images)
   - `GET /api/ingestion/images/{id}/blob` (image bytes)
   - `POST /api/proxy/v1/chat/completions` (LLM 生大綱 / 改寫)
   - `POST http://flux2-dev:8000/generate` (FLUX 生圖)
   - `POST http://pptx-renderer:7100/render` (最終 .pptx)

6. **觀察 csp 不再有 studio 流量**:
   ```bash
   docker logs anila-platform-dev-csp-1 -f --tail 50
   ```
   
   csp **不應該**看到 `/api/studio/*` 進來。看到 ingestion / proxy / auth 流量是正常的。

7. **下載 .pptx**:
   - job state 變成 `done` 時,UI 應該有「下載投影片」按鈕
   - 點下載,Network 看到 `GET /api/studio/slides/jobs/{job_id}/pptx` → 200
   - 開檔確認:
     - FLUX cover hero 圖 OK
     - icon_rows / section_break / image_focus 等 layout 正常
     - 中文沒亂碼
     - 不該有 placeholder「圖片載入失敗」之類

## Pass / Fail 判定

### ✅ Pass

- 從 login 到下載 PPT 全程沒 5xx 錯
- DevTools Network 看到 studio API 走的是 `:8100` / nginx anila-studio route,**不是** csp:8000
- 產出的 PPT 內容跟「Phase 7 前的 csp 端」比沒大幅退化(主觀判斷,基準 = 之前用過的 deck)
- anila-studio container log 看得到對 csp / flux2-dev / pptx-renderer 的呼叫
- csp container log **沒**看到 `/api/studio` 進來

### ❌ Fail(任一觸發)

- `/api/studio/*` 仍然打到 csp(代表 ANILALM proxy / base URL 切換不對)
- anila-studio 起不來(`/health` 503 超過 30 秒)
- JWKS / Redis 任一不通(`ready=false`)
- 生成過程 5xx
- 產出 PPT 缺圖 / 缺章節 / 中文亂碼

## Fail 處置

```bash
git checkout main
gh pr close 12
# 或 git revert PR #12 if already merged

docker compose -f docker-compose-dev.yml down
git checkout main && git pull
docker compose -f docker-compose-dev.yml up -d --build
# Studio 流量回 csp,恢復生產
```

把觀察到的失敗症狀整理給 Claude(包含 docker logs 片段),不用嘗試自己修。

- merge 進 main 之後 prod 環境同樣 cutover(注意 RS256 重登一次)
