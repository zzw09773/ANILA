# 助手快製：建立者手冊

適用對象是會操作網頁與 Office 的單位承辦人。入口是治理中心「助手快製」`/quick-builder`；一般同仁使用已上架助手的入口仍是 ANILA 對話。本文列出操作流程與應確認的結果；正式站操作及三單位 PoC 的完成紀錄見[驗收表](quick-builder-acceptance.md)，不能以本文代替驗收。

## 開始之前

1. 由 ANILA 入口以院內憑證卡登入，確認姓名與所屬單位正確。快製平台共用這個身分，不另申請帳號密碼。
2. 請平台管理員準備可用的模型。模型與嵌入都經平台模型代理；建立者不填模型主機或 API 金鑰。
3. 查詢差勤前，請資料庫負責人準備差勤 MCP，並由平台管理員登錄、核准唯讀工具。不能在畫布填資料庫帳密。
4. 規章問答需先在知識庫建立本單位文件集、上傳核定版本的原檔，並確認逐檔處理成功。請平台管理員在快製平台「管理文件集開放範圍」明確採管來源後，才可送審或執行。助手儲存或公開都不會改變文件集 ACL；文件公開須另由管理員核准。沒有單位歸屬的個人文件集不能直接作為助手的公開來源。
5. 安排另一位有該單位審核權的主管。建立者即使同時是主管，也不能核准自己的助手。

## 第一次建立與試跑

先選情境範本，再展開「助手基本資料」補名稱與模型，依設定提醒補步驟資料。基本資料、三步說明及完整提醒預設收合，畫布與步驟設定可直接操作。「前往設定」會帶到缺件處；清單只協助檢查基本資料，實際執行仍由平台檢查權限與流程。模組庫依用途分組，可搜尋「文件」「判斷」等詞；每個模組列出用途與輸入、輸出，選取後的步驟設定另有例子。先完成基本設定，必要時展開進階設定，原有型別、步數、重試與文件選項均保留。

連線表示資料交給哪一步。點「從此連線」後，依畫面提示點下一步的「接到這裡」；不繼續可按「取消連線」。改接同一出口前先移除舊連線，步驟本身會保留；條件要分別接妥成立與不成立出口。完成後儲存新版本，再到「測試對話」問一題。

試跑會顯示伺服器實際開始及完成的步驟。「執行中」尚未代表成功，耗時以步驟完成後的紀錄為準；沒有走到的條件分支不會假顯進度。可安全顯示的最後模型回答會逐段更新，非最後一步、結構化或待遮罩內容可能須等待驗證後才出現。先看答案與「這次怎麼完成的」，失敗步驟可按「調整這個步驟」回去修改，另存新版本後重試。「查看詳細紀錄」保留經權限檢查與遮罩的輸入、輸出、耗時、檢索引用、工具參數與結果、模型完成資訊；基本操作不必理解 JSON。

每次試跑先建立請求識別碼；畫面取得伺服器紀錄後顯示執行編號與實際狀態。「停止等待」只中止目前回覆的等待，不會取消伺服器執行，畫面仍查詢同一次試跑。重新整理後選回同一助手與「測試對話」，會重新檢查目前身分、單位、助手、版本、模型與來源權限，再找回執行中或已完成的紀錄；查詢不會重新派發。瀏覽器只記錄識別碼及版本等指標，不保存問題、答案或工具資料。瀏覽器禁止保存時，可按「查詢我的試跑」查看目前版本最新二十筆本人紀錄，再選要查的執行編號。

要停止伺服器的這次試跑，按「取消伺服器執行」並確認。只有收到伺服器保存的取消狀態，畫面才會確認停止；已經完成的執行仍顯示原結果。取消會阻止後續步驟與結果交付，已送到外部服務的查詢可能仍需時間收尾，不能把部分回答視為完整答案。取消回覆失聯時，先查詢同一次試跑，不要連按另送問題。

`TEST_RESULT_UNKNOWN` 表示尚未確認伺服器狀態，不能當成未執行、成功或已取消；先按「查詢這次試跑」。即時連線中斷或資料過大時，畫面會改查原執行紀錄，不重新派發。若長時間無法確認，可在停止等待後按「結束查詢，準備另一個測試」，確認原執行可能仍在進行，再另行送出新測試；這會是另一次執行。服務程序失聯且執行權到期後，查詢會顯示「執行已中斷；結果尚未確認」（`RESULT_UNCONFIRMED`），不自動重跑，也不表示已證實外部查詢失敗。未保留可追蹤紀錄的舊試跑，無法自動精確找回。結果標示受測版本，修改後須重新試跑，不能用舊結果確認新版本。

在另一分頁登入或登出、登入身分變動，或助手操作被判定無存取權限時，頁面會立即清除原帳號的助手內容、未儲存修改、問題、模型設定、畫布及試跑明細，並顯示不含原內容的說明。按「重新確認身分」重新載入，確認目前登入者；只有通過現行授權後，才可從伺服器重新讀取已儲存版本。未儲存內容不會保留或自動還原，即使重新登入原帳號也一樣。換帳或清除畫面不等於取消伺服器執行；需要確認試跑時，重新驗證後查詢本人有權存取的原紀錄。

## 範例一：差勤與請假查詢

1. 打開「助手快製」，按「建立助手」。在「情境範本」選「差勤請假」，再按「套用範本」。確認範本的用途說明符合單位需求；沒有合適範本時請管理員確認範本目錄。
2. 填「助手名稱」，例如「人事差勤查詢」；「用途說明」填可查詢的項目與適用人員。選擇「平台模型」、合適「密等」，保留「開放範圍：本單位（預設）」。密等與開放範圍分別控制資料分類與使用對象，不能互相取代。
3. 在「流程畫布」選取「工具查詢」步驟。在「步驟設定」選已核准的「請假餘額」或「打卡紀錄」工具，依工具說明填日期等查詢條件。設定區在寬螢幕位於畫布右側，較窄螢幕則移到下方；按「顯示步驟設定」可展開已收合的設定。不要把建立者員工編號當成每個人的固定查詢身分。工具每次都應以實際提問者的短效 JWT 查詢，由 MCP 判斷可見資料。
4. 若需加步驟，可從模組庫拖入，或按模組名稱加入。選取步驟後填設定；可拖曳步驟標題移動，或讓標題取得焦點後以方向鍵移動。畫布上方的「縮小」「放大」「100%」只改檢視比例；「適合畫面」可查看流程全貌。需要更多空間時按「收合步驟設定」；畫布也可捲動。「整理排列」會重新排放步驟並避開重疊，保留原有連線與設定，須儲存新版本才會保留這個排列。
5. 用「從此連線」與「接到這裡」，或下方「流程連線」的起點與終點建立順序。條件判斷需分別連接「成立」及「不成立」，例如依日期欄位是否缺漏分流。只使用下拉選單提供的比較方式，流程不能形成循環，也沒有程式碼、自訂運算式或外掛欄位。
6. 若使用「多步驟代理」，僅勾選所需的核准查詢工具，設定最多步數與重試次數。預設 5 步、重試 1 次；達上限應停止並回報，不能自行增加工具或改成寫入動作。
7. 按「儲存新版本」。切換到「版本與審核」，記下版本號。每次儲存新增不可變版本，包含名稱、模型、密等、流程、文件集與開放範圍；後續修改不覆寫這份內容。
8. 到「測試對話」，確認上方版本號，輸入「我這個月還有幾天假」之類的測試問題，按「傳送測試」。測試使用目前登入者的權限。展開逐步紀錄，核對輸入、輸出、工具參數與結果、耗時及錯誤。
9. 用兩位經授權的測試人員各自登入重做測試，核對兩人的結果只包含本人資料。另測試無資料、日期不合法、服務中斷及無權限情況；不得以共用帳號測出一次成功就代替身分隔離測試。
10. 回到「版本與審核」，選擇已測試的版本，按「送主管審核」。送審鎖定該版本；主管核准內容不會隨其他草稿變更。已有版本待審時，先由主管完成或退回該版本，再送另一版。
11. 主管核准後，選同一版本按「註冊為 Agent」。此時只是送到既有平台登錄流程，仍須平台管理員在 Agent 管理核准，才可在 ANILA 對話使用。
12. 管理員核准後，請本單位一般同仁從 ANILA 的 Agent 選單選擇助手，重做本人差勤查詢；這才是發布後的使用確認。

## 範例二：規章問答

1. 在知識庫建立本單位文件集，命名並標註密等，上傳規章 PDF、DOCX 等原檔。逐檔確認處理狀態；失敗的檔案不能當成已可檢索。掃描件、舊 Office 及程式碼的處理限制見[維運手冊](quick-builder-operations.md)。
2. 回到 `/quick-builder` 建立助手，套用「規章問答」範本。填名稱、用途、模型、密等與開放範圍。
3. 請管理員先採管文件集開放範圍。「本單位」精確限制為文件集所屬同一單位；指定單位或全院須另行核准。選「文件檢索」，勾選已採管且有權使用的規章文件集。「最多取回幾段」預設 5 段；先保留預設值，用實際問題評估後再調整。
4. 選「提示詞與角色」步驟，填寫規章問答的工作範圍與資料不足時的處理方式；「對話輸出」保留「附上來源依據」。這些欄位是助手內容設定，不能變更平台的身分、來源權限或安全規則。
5. 儲存新版本並試問「出差申請需要哪些文件」。展開「檢索文件片段與來源」，回到原檔核對條文、檔名、頁碼／投影片編號／行號。另用條號、專有名詞測試關鍵字命中，以及文件未載明的問題。
6. 如使用「文件草稿」，在「文件產出方式」選「純文字範本」輸出 RTF，或選「既有 Studio 文件範本」排版前一步內容。填「文件標題」；Studio 模式選「深度技術綜述」「重點摘要」「教學講義」或「對外溝通文件」之一，以及 HTML、PDF 或 DOCX。這四種是固定版型，不接受上傳任意 Office 範本；Studio 此步只排版，不另呼叫模型或 RAG。儲存版本後測試，完成時按「下載文件草稿」取回並人工檢核。固定版型轉檔已有離線工程證據，正式院內串接仍待驗；第一期不會代為送出公文、請假、預約或修改資料。
7. 確認引用正確後，按差勤流程第 10–12 步送主管審核、註冊並等待平台管理員核准。

## 修改、回復與停用

- 修改任何已發布內容，包括模型、密等、來源或開放範圍，都要「儲存新版本」、測試並重新送審。在新版獲主管及平台管理員核准前，舊的已發布版本繼續服務。
- 「比較兩個版本」可查看兩版差異。選舊版按「回復為新草稿」會新增一版，仍須測試及重新審核，不會直接讓舊版取代線上版。
- 退回後查看審核說明，修改並另存新版本再送審。不要將已退回版本當成新的審核內容。
- 要開放「指定單位」時，填管理員確認過的單位編號；「全院」也須重新審核。公開助手不會自動公開文件集，其他單位仍可能因來源權限不足而無法執行。文件本身的公開由管理員另行採管，不因儲存助手而改變。
- 按「停用助手」並確認後，核對 ANILA 端同步不可使用。恢復時先另存新版本，再測試、送主管審核、註冊及等待平台管理員核准；停用前的舊候選版本不能重新核准復活。
- 快製助手對應的 Agent 受管理護欄保護，不能在一般 Agent 頁直接修改或刪除；變更走快製新版本流程，下架走「停用助手」。
- 已採管文件集的寫入限平台管理員，或仍在精確所屬單位的文件集建立者；讀取或公開權限不等於可上傳、修改、刪除原檔。範本引用的公開來源被撤回後，一般使用者不再看到該自訂範本。
- 文件產出與下載都檢查有效密等。產檔後若原任務或對話升密，產物可能被清除或下載被拒；請依單位程序處理，不以舊網址繞過。執行脈絡保存在伺服器，不需在畫布填任務或對話身分。

## 常見情況

文件出現 `E_CHUNK_TOO_LARGE`，表示單一函式、表格、投影片或程式區塊超過平台完整結構上限；請拆小該結構或分檔後再上傳，內容不會自動截斷。程式碼來源若顯示保守分界，請依原檔行號確認函式範圍。

測試步驟中的「模型內容調整」表示模型呼叫前為符合內容長度而改用相關片段或省略部分來源。已完成的文件檢索與模型步驟保留當時紀錄；後續調整另列，不會改寫先前模型實際使用的來源。回答不代表已參考被省略的完整文件。

| 畫面／錯誤類型 | 處理方式 |
|---|---|
| 沒有可選模型、文件集或工具 | 請管理員確認模型授權、文件集單位權限、MCP 登錄及核准狀態；不要改填外部連線 |
| `GRAPH_LAYOUT` | 步驟重疊或位置太近時，部分連線暫時無法清楚顯示；按「整理排列」或拖開步驟後再確認成立與不成立分支 |
| `VERSION_CONFLICT` | 在原帳號與權限仍有效時核對需重做的修改；重新整理後確認伺服器已儲存的新版本，不依賴未儲存內容自動還原 |
| `IDENTITY_CHANGED`，或助手讀取／操作回覆 401／403／404 | 原帳號內容與未儲存修改會清除；按「重新確認身分」，通過目前身分及權限檢查後，重新選取已儲存版本。回到原帳號不會還原未存內容 |
| `REVIEW_PENDING` | 確認正在審核的版本，待主管核准或退回後再送下一版 |
| `SELF_REVIEW` | 改由另一位有權限的單位主管審核 |
| `MODEL_SERVICE_ERROR`、`MODEL_SERVICE_UNAVAILABLE` | 模型服務未完成回答或無法使用，請稍後重試或由管理員確認模型服務狀態；這不等於本人沒有權限 |
| `MODEL_DENIED` | 目前帳號沒有模型使用權限，請管理員確認授權 |
| `PROVIDER_ERROR`、`PROVIDER_UNAVAILABLE` | 服務未完成或不可用；來源不明時不推測是模型或授權問題，請提供錯誤類型給管理員 |
| `TEST_REQUEST_BUSY`、`TEST_REQUEST_CONFLICT` | 請先查詢這次試跑；忙碌可稍後用同一識別碼重試，不同內容或版本不能沿用舊識別碼 |
| `TEST_RUN_BUSY` | 同時試跑已達工程資源上限，伺服器未建立新執行；先查詢原識別碼，稍後再試 |
| `RESULT_UNCONFIRMED`、`TEST_RUN_INACTIVE` | 查詢同一次試跑確認保存狀態；系統不會自動重派，不能把它當成已成功或人為取消 |
| `SOURCE_UNAVAILABLE`、`TOOL_UNAVAILABLE` | 來源每次執行都重新檢查；請管理員核對來源是否撤權、停用或取消核准 |
| `SOURCE_GOVERNANCE_REQUIRED`、`SOURCE_DEPARTMENT_REQUIRED` | 請管理員先確認文件集單位歸屬並採管開放範圍；個人庫應先建立有單位歸屬的文件集 |
| `TOOL_CHANGED` | 工具參數與核准快照不一致，請重新確認設定、另存版本並送審 |
| 已註冊，但 ANILA 仍無法使用 | 請管理員確認 Agent 是否已核准、使用者授權、來源權限及密等，並核對線上版本 |
| 回答空白或模型憑證失敗 | 請管理員到既有模型頁處理；不要把金鑰貼在問題、用途說明或工作指示 |
| `MODEL_OUTPUT_LIMIT` | 回答已達輸出長度上限，內容尚未完成；請縮小問題或接續提問。快製助手不提供直接續寫按鈕，接續提問會重新執行流程 |
| `MODEL_CONTENT_FILTER` | 回覆因內容限制未完整提供，請調整問題後再試；空白回覆也會保留這項說明 |
| `MODEL_ACTION_REQUIRED` | 模型要求工具處理，這次回答尚未完成；請聯絡助手建立者確認流程設定 |
| `MODEL_COMPLETION_INVALID` | 回覆結束資訊不合法，無法確認回答是否完整；請重試或提供錯誤類型給管理員 |
| HTTP 502、`FLOW_FAILED` | 這次流程未完成；模型結束原因與可確認用量會保留在失敗回覆，重新載入仍可確認。請稍後重試或聯絡助手建立者，不能把前一步模型已結束視為整個流程成功 |
