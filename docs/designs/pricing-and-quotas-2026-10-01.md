# 模型計價與用量額度

2026-10-01 擁有者決定：計價與額度先做好，交給管理員設定。預設不計價、不限制，所以上線時行為和現在一樣。

## 計價

- 治理中心「模型」頁，每個模型可以填單價（每百萬 token）：輸入、輸出、思考三種。
  - 思考沒填時，以輸出價計。
  - 輸入與輸出都有數字才算已計價。只填一邊、或呼叫當時沒有生效價格，都是「未計價」，不當成 0 元。
- 單價有生效日期。改價時新增一筆價格，不覆寫舊的。生效時間不能早於現在五分鐘以上；要更正更早的歷史必須另走明確流程，不能靠回溯生效日。
- 成本在查詢時計算：每一筆用量依「呼叫當時生效的單價」計。同一群組先把未捨去的分子加總，再換算成 micros。
- 貨幣全平台一種，預設 `TWD`。一旦已有單價或金額額度，貨幣就鎖定，不能再改。
- 改價要寫稽核。

## 報表

- 「用量」頁加上成本欄。全部未計價時就不顯示成本欄。
- 新增兩種切法：依 **API 金鑰**、依 **單位（含下層）**。
- 匯出可以選任意起訖日期，加上「本月」「上月」「本季」快捷鍵。
  - 單次匯出最長一年。
  - 匯出的 CSV 帶成本欄。
- 「API 金鑰」頁顯示每把金鑰本月用量。

## 額度

- 對象有三種：**單位**、**使用者**、**API 金鑰**。
- 期間有兩種：**每日**、**每月**，依平台時區（Asia/Taipei）計。
- 計量單位有兩種：**token** 或 **金額**。金額只有在這個對象實際可用的模型都已完整計價（輸入與輸出都有價）時才能選。期間內沒有生效價格的用量不計入金額額度，額度頁顯示「期間內有 N 筆未計價用量，未計入金額」。
- 每條額度都有：
  - **上限**：留空代表無限，這也是預設。
  - **提醒門檻**：預設 80%。到達時通知對象本人與管理員。
  - **到上限時**：「只提醒」或「擋下」。
- 單位額度涵蓋該單位與所有下層單位的用量總和。
- 一筆呼叫同時受多條額度約束時（自己、所屬單位、上層單位、金鑰），任何一條擋下就擋下。
- 被擋下時：
  - 回 HTTP 429 加中文訊息，說明是哪一條額度、何時重置；
  - ANILA 畫面上顯示同樣的訊息；
  - 用量頁看得到誰被擋過。
- 判斷要快，不能每次呼叫都掃整張用量表：
  - 用 Redis 計數（依期間分鍵），寫用量時一併累加；
  - 計數遺失時，從資料庫重算當期總和；
  - Redis 不在時不擋，照常放行，並記一筆警告。理由與現有的公平排隊相同：平台要活著。
- 已經開始的串流不會中途切斷；額度只在呼叫開始前檢查。已經在途的呼叫不會被取消，所以實際用量最多超出同時在途的呼叫數。
- 預檢、計數與計價用同一個呼叫開始時間（UTC）。提醒門檻在用量寫入後判斷有沒有跨過；同一額度、同一期間只通知一次。
- 誰能設定：
  - 管理員可以設定全部額度；
  - 單位管理員只能看自己單位的額度與用量，不能改；
  - 所有修改都要寫稽核。

## 不做

- 自動扣款或對外帳單。
- 依時段變價。
