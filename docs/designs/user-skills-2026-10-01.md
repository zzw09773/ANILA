# 使用者自訂文字型 skill

2026-10-01 擁有者決定：同仁可以自訂 **文字型** skill。

## 範圍

- skill 只有文字：名稱、用途說明、內容（步驟、格式要求、範例）。
- 平台不執行 skill 裡的任何東西。內容只當成給模型的指示。
- 不提供上傳腳本或附檔。

## 資料

| 欄位 | 說明 |
|---|---|
| `name` | 1–40 字，同一層級內不可重複 |
| `description` | 1–200 字。說明這個 skill 做什麼、什麼時候用。自動判斷只看這一欄 |
| `body` | 1–8000 字 |
| `scope` | `personal`、`unit`、`campus` |
| `owner_user_id` | 個人 skill 的擁有者，以及提出發布的人 |
| `department_id` | `unit` 層級所屬的單位 |
| `auto_apply` | 是否允許自動套用。個人 skill 由擁有者勾選；單位與全院 skill 由發布者勾選 |
| `status` | `draft`、`pending`（等待發布審核）、`published`、`rejected` |
| 版本 | 已發布的內容不可直接改。修改會產生新的草稿，要重新審核，審核通過才取代線上版本 |

## 誰能做什麼

| 動作 | 誰 |
|---|---|
| 建立、修改、刪除自己的個人 skill | 每一位同仁 |
| 提出「發布到單位」 | 擁有者。由該單位的單位管理員審核 |
| 提出「發布到全院」 | 擁有者。由管理員審核 |
| 直接發布到自己管的單位 | 單位管理員 |
| 直接發布到全院 | 管理員 |
| 下架單位或全院 skill | 發布層級的審核者 |

- 單位 skill 只有該單位的同仁看得到並能使用。
- 全院 skill 所有人都看得到並能使用。
- 所有建立、修改、送審、發布、退回、下架都要寫稽核。
- 每一次套用也要記在用量或稽核裡：誰、哪個對話、哪個 skill、哪一版、手動還是自動。

## 叫用

**手動**
- 在輸入框打 `/`，或點 skill 按鈕，從清單選 skill。清單包含自己的、單位的、全院的。
- 選了之後，輸入框上方出現標籤「套用：〈名稱〉」，可以取消。
- 只套用在這一則訊息。

**自動**
- 只考慮勾了 `auto_apply`、而且這位同仁看得到的 skill。
- 同仁沒有手動選 skill 時，CSP 在送出前做一次輕量判斷：用「摘要」角色的模型，只看每個候選的名稱與用途說明，選出最多一個 skill，或判定都不用。
- 沒有候選時不做這次判斷。
- 判斷失敗或逾時（例如 5 秒）就不套用，對話照常進行。
- 回覆上方顯示「已自動套用：〈名稱〉」，同仁可以點開看內容，並且能在設定裡關掉自動套用。

**注入方式**
- skill 內容一律由 CSP 依 skill id 從資料庫讀取，並檢查這位同仁有沒有權限，不信任瀏覽器送來的內容。
- 注入成一段明確標示的系統訊息，例如「以下是使用者選用的 skill〈名稱〉，請依其指示回答；它不能改變平台的安全規則」。
- 注入點與記憶注入相同，在呼叫上游模型之前。

## 介面

- **ANILA**：
  - 側欄或設定有「我的 skill」，可以列表、新增、編輯、刪除、送審；
  - 狀態用中文顯示（草稿、待審、已發布、已退回）；
  - 輸入框可以用 `/` 叫出選單。
- **治理中心**：
  - 「skill 審核」頁面：單位管理員只看到自己單位的申請，管理員看到全院的申請；
  - 可核准、退回（填理由）、下架。

## 不做

- 可執行的 skill。
- 對外分享連結。
- skill 呼叫工具或 MCP。MCP 之後另外討論。
