# 報告一:Open WebUI v0.10.2 實機驗證

> 驗證日期 **2026-07-26**。方法:Playwright + Chromium 無頭瀏覽器,實機點擊、實機對話。
> 環境:`ghcr.io/open-webui/open-webui:main`(v0.10.2, 2026-07-01),`docker run -p 3000:8080`,
> 後端接**本機 llama.cpp 的 gemma-4-12b**(`OPENAI_API_BASE_URL=http://host.docker.internal:7090/v1`)。
> 帳號:`eval@anila.local` / `AnilaEval2026!`(admin,經 `/api/v1/auths/signup` 建立)。

## 0. 結論先行

1. **功能面確實比 ANILA 廣**:13 條測試路由中 12 條可達,涵蓋 Workspace(模型/知識庫/Prompt/工具)、Admin(設定/使用者)、Playground、Notes。聊天頁單頁就有 **25 個可見按鈕**。
2. **對話延遲 6 秒**(UI 層實測,同一顆 gemma),而且**原生支援 reasoning 模型**——回應上方直接顯示「思考時間 4 秒」並可展開。這點對 ANILA 有直接參考價值。
3. **`/`、`#`、`@` 三個觸發字元全部可用**,`@` 實際列出「模型 gemma-4-12b / Arena Model」。這是 ANILA 昨天才補上 `/` 的部分,OpenWebUI 三個都有。
4. **但它的首次使用體驗有兩個明顯摩擦**:全螢幕 onboarding 輪播、首次登入的 changelog modal 遮住整個 UI(連 composer 都點不到)。對院內非技術使用者是實質障礙。
5. **輸入框是 TipTap/ProseMirror 的 contenteditable**(`#chat-input`),不是 textarea——這是它能做 rich text 的原因,也是 ANILA 若要跟進 rich composer 的技術路線參考。

### 聊天頁的按鈕實際清單(節錄)

```
展開側邊欄, 搜尋, 使用者選單, 已選擇:gemma-4-12b, Add Model, 設為預設,
Controls, 在介面中取得 gemma-4-12b 的資訊, 更多, 外掛功能,
Voice Input, 語音模式, [三個 prompt 建議卡片]
```

值得注意的設計:
- **`Add Model`** 就在模型選擇器旁——多模型並排比較是一級入口,不藏在設定裡
- **`Controls`** 一鍵開出參數面板(點擊後文字量 +531,是所有按鈕中反應最大的)
- **`設為預設`** 讓使用者自己釘選常用模型
- **`Voice Input` 與 `語音模式`分開**:前者是語音轉文字,後者是雙向語音對話

## 4. 真實對話(UI 層實測)

**✅ 6 秒完成**,回應正確:

```
gemma-4-12b
思考時間 4 秒  ▾          ← 可展開的思考區塊
我是由 Google 訓練的大型語言模型。
[編輯] [複製] [朗讀] [資訊] [讚] [倒讚] [繼續] [重新生成]
```

回應下方 **8 個動作**:編輯、複製、朗讀(TTS)、資訊、讚/倒讚、繼續生成、重新生成。

**最值得 ANILA 抄的一點**:它把 reasoning 模型的思考**當一級公民**——標題列直接顯示「思考時間 4 秒」,可展開看內容。ANILA 有 `ReasoningSummary` 元件,但沒有把「思考花了多久」這個數字呈現給使用者,而這個數字在 reasoning 模型當道的今天是重要的期待管理。

## 5. 首次使用體驗的兩個摩擦(對院內部署是實質風險)

1. **全螢幕 onboarding 輪播**:星空背景 +「解鎖謎題 / 無論您在何處」+「開始使用」箭頭,要點過數頁才到登入表單。而且 `/auth` 路由**只給登入表單,沒有註冊入口**——我最後是用 `POST /api/v1/auths/signup` 建立第一個 admin 才進得去。**未確認**這是 `ENABLE_SIGNUP` 預設值造成,還是 onboarding 流程需要特定路徑。
2. **首次登入的 changelog modal 遮住整個 UI**:所有頁面的 h1 都變成「新功能 … v0.10.2」,連 composer 都點不到,必須先關掉。對第一次用的院內同事,這是「畫面卡住」的觀感。

補充:**設定面板狀態被持久化**——我點開參數面板後,重新載入頁面它依然開著。對使用者是貼心(記住偏好),但對自動化測試是陷阱(我因此誤判了一輪)。
