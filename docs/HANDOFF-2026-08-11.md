### 🔬 方法論:② 是「活體重現勝過讀碼猜測」的教科書案例

我在原始碼裡繞了**七、八輪**都沒找到截斷點(排除了前端組訊息、csp 出向、中文正規化、
agents 表模板…),因為**我一直假設那是「使用者的問句被某個函式切掉」**。
真相是**根本沒有函式切它**——是 Router 在**串流途中**用正規表示式判斷,
而緩衝區結尾被誤認成行尾。

轉折點是**回到資料**:
1. 用平台自己的估算器算「完整 20 字＝20 tokens／截斷＝11」,對上日誌的 `prompt=11`;
2. 從 `token_usage` 發現那一輪有**兩發**請求,`completion=1359` 對得上畫面「1305 字思考」;
3. 於是知道第二發才是轉派,**而它的問句是第一發產生的**;
4. 在 `messages.metadata->>'reasoning'` 裡找到模型**寫對了**的原句;
5. 最後用**純 regex 最小重現**證實守衛的洞。

👉 **下一手的教訓**:當「讀碼找不到」時,不要再讀第九遍——**回去問資料**
(用量、時序、DB 裡存的東西)。而且 ⚠ **不要用「暴力呼叫每個函式」去掃**:
我試過,結果**執行到一個 CLI 進入點**。那個方法不安全,已停用。

### ⚠ 環境事實:在主樹跑 `packages/anila-core` 的測試會在 collection 就炸

```
card_dev_trust_test_ca — Extra inputs are not permitted [extra_forbidden]
```
原因:主樹有 `.env`,而 anila-core 那邊的 settings 模型是 `extra="forbid"`
(csp 自己的 `config.py:145` 是 `extra: ignore`,所以**跑著的平台沒事**,
compose 傳的也是具名變數)。
👉 **要跑 core 測試就到 worktree 跑**(那裡沒有 `.env`)。
⚠ 這條的價值在於**錯誤訊息會把人指向完全錯的方向**——看起來像設定壞了,其實是跑錯地方。

### 殘留風險(記錄,不修)

**② 修好的是「緩衝區結束被誤認成行結束」。但如果模型自己在查詢中間換行**
(`DISPATCH:a:前半\n後半`),那行 DISPATCH **真的**結束在換行處,查詢**真的**只有前半——
守衛會放行,而且那是對的。**那是模型輸出品質問題,不是這個缺陷。**
本次事故的證據顯示模型寫在同一行,所以完全由守衛的洞解釋。

### 一個正例,值得跟教訓一樣被記住

luna 在 ② 的報告裡**主動列出一條對自己不利的 lint 訊息**(`F821`),並說明是既有的。
