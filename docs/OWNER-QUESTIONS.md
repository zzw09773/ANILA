## ✅ Q36 — 要不要加憑證偵測(2026-08-06,當日裁決)

> **✅ 已答:加,而且只接到「警告」。** 擁有者原話:「好『警告』就好」。

**問題**:偵測器的四條規則是身分證、電話、Email、信用卡。
**API key、bearer token、私鑰區塊、密碼欄位,一條都不抓**——
也就是說,**擁有者自己用來描述這個功能該長什麼樣的那個例子,是這個功能唯一完全沉默的情況**。

**成本(實測)**:下游全部跟種類無關(提示列、摘要、閘門只讀 `label`／`index`／`value`),
所以新增一種就是**規則陣列裡多一個物件**,不動其他檔案、沒有新模式、沒有 migration。
有前綴的形式(`sk-`、`ghp_`、`AKIA`、`BEGIN … PRIVATE KEY`、`Bearer ey…`)約半天。

**為什麼只接警告**:憑證誤判如果會**擋住貼程式碼的人**,比表格誤判更糟。
⚠ 施工要求:「憑證不得進入阻擋判斷」要做成**結構性的**,不是一句未來會被忘記的慣例,
並且要有測試在憑證命中跑到閘門時轉紅。

**明確不做**:泛用的高亂度／長度啟發式。它會對任何 base64 或十六進位字串響,
在這裡就是**對貼程式碼的人一直響**;那是另一個沒被問過的決定。

**同批順帶修(不是政策,是 bug)**:身分證加檢查碼與首碼限制、信用卡加 Luhn、
分隔符字元集去掉換行——現行規則會把採購案號、預算欄、年份列表、表格直欄數字全部認成個資。

## ✅ Q34 — 沒有文字的空白表單,要不要至少用檔名找得到(2026-08-05,已答:不做)

**問題**:擁有者回報「大型空白表格在內網建不了索引」。實測結果是——

- **沒有 chunk 層級的語意判斷,系統裡沒有那種東西**。唯一的判定在整份文件層級:
  `packages/anila-core/src/anila_core/ingestion/parsers.py:132-138`「抽取後零文字即毀損」。
- **DOCX 的空白表格可以正常索引**;症狀只發生在**沒有文字圖層的 PDF／掃描檔**。
- 而使用者只看到「失敗」兩個字,因為**失敗原因存了卻沒有畫出來**(見 FAKE-CONTROLS #55)。
  **擁有者的誤診就是這一條造成的。**

**為什麼需要你決定**:一份「完全沒有文字的空白表單模板」,使用者上傳它通常是為了讓同事**找得到並下載**,
不是為了問它問題。要支援這件事,就要在零文字時索引一個**只有檔名**的片段。

- **要**:多一個誠實的子狀態(UI 要明講「僅檔名索引,內容無法檢索」)。
  代價是多一個狀態要維護,而且不誠實地做會變成新的假控制項。
- **不要**:維持清楚失敗＋顯示原因。使用者知道發生什麼事,但那份檔案在平台上找不到。

**我現在照什麼在做**:**不做**。先把 #55 的失敗原因畫出來——那是一行 UI,不動匯入邏輯。
⚠ 無論怎麼決定,**都不要**為此引入表格結構解析那類重依賴,那正對著「越複雜就被放棄」那條教訓。

**改變主意的成本**:低,而且是加法。等真實使用者抱怨「我的表單不見了」再做也不遲。

### ⚠ 2026-08-05 量測:這題的受益範圍比原本寫的**大**

fable5 實測(代理模型,排序方向可信、絕對值待 P5.5 對真端點校準):

| 量測 | 數字 | 意思 |
|---|---|---|
| 最有利查詢 vs 空白表格 chunk | **0.053** | 輸給無關的真文字(0.457) |
| **兩張不同**的空白表格互比 | **cos = 1.000** | 向量檢索**永遠**分不出請假單模板與測試紀錄表模板 |
| 空白 chunk 對各種查詢 | 0.04–0.16 | 一律墊底,不劫持排序 |

**兩個結論改變了這題的框架:**

1. **「成功索引」的空白模板一樣找不到。** 它會顯示「已索引 ✓ 12 段」,而任何內容查詢都撈不到它——
   **「以為發生了什麼」的形狀現在就在線上**,不限於解析失敗那條路。
   所以 Q34 要處理的不只是「零文字的檔案」,是**所有沒有可檢索文字的檔案**。
2. **不需要做任何過濾器。** 我原本擔心空白 chunk 是噪音會拖累檢索——**量測推翻了**:
   檢索是集合隔離的、空白 chunk 一律墊底、聊天 RAG 還有 0.3 地板擋著。
   **它是死重,不是毒藥。** 過濾它、標記密度、寫抽取器,全部不必做。

**所以真正的選項只剩一個**:要不要讓**檔名進檢索**。做了同時關掉「掃描空白件」與「有文字圖層的空白模板」兩種殘留需求;不做就維持「靠側邊欄用檔名瀏覽」。
📌 **附帶結論**:對這類文件,**檔名取得好不好比內容重要**——這句話值得寫進使用者手冊。

## ✅ Q31 — Router 直答的接地設計(2026-08-05,fable5 裁決,已採納)

> **記錄用,不需要你回答。** 擁有者 08-05 指定要問 fable5,結論如下,已採納為施工規格。

**背景**:Router 直答目前**完全不做檢索**——`collection` 這個字在 Router 三千多行裡出現零次。
而它的提示詞裡**已經寫著**「有提供檢索段落時,僅根據段落內容回答並附 [N] 來源標註」,
那條指令因為沒人餵段落而是死的。看提示詞會以為功能存在。

**採納的形狀:單次呼叫、先檢索**(段落注入 `router_server.py:1002` 組 `routing_messages` 之處)。

⚠ **我原本提的「先分類、再檢索」被否決,理由值得記**:分類的時候還沒看到段落,
模型是在**盲判**「我自己答不答得了」——而「要看到段落才判斷得了」正是這件事的前提。
**那個方案邏輯上不成立,不只是比較貴。**

**成本不是取捨**:嵌入約 50–150 ms,一次完整 LLM 回覆是秒級,差 10–50 倍。
「被派走的查詢白做檢索」的浪費是每題約 20 ms。不值得為它設計任何東西。
模型搬到算力中心之後,LLM 那側只會更貴,差距更大。

**紅線**:Router 的服務憑證**必須 scope 鎖死在那一個集合**。給它一把能搜任意集合的鑰匙,
等於在認證邊界前面開一個跨租戶讀取口。驗收要含「Router 憑證搜其他集合 → 403」。

**雙生分支**:注入點天然只有一個(`:1002` 餵所有路徑),但 **metadata 出口是兩份**
(`:1137` 的 `_merge_anila_meta` 與 `:1862` 的 streaming meta event)。防漂移要三件:
共用 helper、同 fixture 跑 `stream=True/False` 斷言兩邊 citations 相等且非空、
以及把注入那行拿掉時兩個測試都必須紅。

### ⚠ 一個會讓整個功能靜默失效的陷阱

**天真地把相似度門檻設成 0.7,會永遠濾光所有段落,而系統看起來完全正常。**
NV-Embed 是**非對稱**的:同一句話的 query 側與 doc 側,餘弦本來就只有 ≈0.70。
設 0.7 等於設在「完全相同的句子」那條線上。
**門檻必須在部署的真模型上量出實際分布再定,而且 trace 要看得見段落數。**

其餘假控制項清單與各自的排除證據,見 fable5 裁決全文(交接文件引用)。

## ✅ Q28 — 附件解析:UTF-16 只支援英數為主的檔案(2026-08-02;**08-03 擁有者追認**)

> **✅ 已答(2026-08-03):「對,先維持」。**
> 契約正式成立,不再回頭做「這是真中文還是亂碼」的判斷——那正是燒掉十三輪的東西。

**裁決內容**:上傳的檔案若是 UTF-16 編碼,**只在「解碼後英數字元超過一半」時接受**;
以中文(或其他非英數文字)為主的 UTF-16 檔案**拒收**,並顯示「請另存為 UTF-8 後再上傳」。
UTF-8 完全不受影響——中文為主的 UTF-8 檔案照收,任何長度、有沒有標點都一樣。

**為什麼要這樣**:這條之前燒了**十三輪**。每一輪的做法都是加一條規則去猜
「這段解碼出來的非英數文字,是真的文字還是二進位亂碼」,然後:

- 猜鬆一點 → 執行檔被當成文章收下並計費(實測 `/bin/ls` 未經修改就通過,計了 2342 個 token)
- 猜嚴一點 → **正常的中文文件被整份拒收**(實測記事本存的中文備忘、你自己 repo 的 `CLAUDE.md`)

兩者是**同一條繩子的兩端**:擋住執行檔的那道門檻,同時在擋中文。

新契約跳出這個迴圈的原因:**它從頭到尾不看非英數的那一半**——不看語言、不看用了幾個
不同的字、不看標點。二進位讀成 UTF-16 幾乎必然滿是非英數字元,所以是**用數的**被擋掉。

**代價**:中文為主的 UTF-16 檔案要重存成 UTF-8。實務衝擊小——Word 與 PDF 走完全不同的
解析器(`DocxParser`／`PdfParser`),根本不經過這條路;記事本存「Unicode」的中文備忘會被拒,
但訊息明講怎麼自救,三秒可解。

**前例**:與你 Q24 對 Big5／CP950 的裁決同一個邏輯——**看得見的失敗,勝過看起來對其實錯的結果**。

**改變主意的成本**:高。不同意就得回頭做「真中文 vs 亂碼」的判斷,那正是燒掉十三輪的東西。

## Q10 — ~~治理中心不在本機這套裡~~ **這條是我查錯,已作廢**(2026-07-31)

**原本寫的結論是錯的。** 治理中心**有**在部署,而且一直都在:

csp 掛載 `/assets` 並送出 index.html,nginx 的 `location /` 又 proxy 到 csp。
所以打 `https://<主機>/` 進去的就是它。

**我怎麼會查錯**:去看了 `services/csp/Dockerfile`(那支存在,但**不是** compose 實際用的),

`infra/docker/csp.Dockerfile`,而那支裡面根本沒有 "governance" 這個字串以外的線索。
擁有者一句「但我有進入 csp 啊」才逼出正確答案。

`docker inspect` 看映像、`docker exec` 看檔案實際在不在,比 grep 原始碼可靠。
