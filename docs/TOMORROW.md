## 四、你那個 API key 的例子，現在有答案了

你說「就像我貼 apikey 給你一樣」。實測結果：**這個偵測器對那把金鑰一個字都不會說。**

四種憑證形式（API key、bearer token、私鑰、密碼）**全部靜默**。而它會誤判的東西是：採購案號、預算欄、年份列表、表格裡的直欄數字、公文裡的 email。

**十條合理的院內文本，十條全部誤中。**

所以今天在做兩件事：把那四條規則的精度修對（檢查碼、Luhn、分隔符），以及照你的裁決加憑證偵測、**只接警告**。

**閘門現在綠了（08-07 凌晨補完）**，但過程挖到一件你會想知道的事：

**asr-decoder 那些 IDS 日誌不是誰複製進去的。** 是**這台開發機的 Symantec DCS 資安代理，在容器執行 build 指令的當下，把自己的目錄塞進容器裡**，然後就被封進映像。用一個完全沒有複製任何檔案的空映像就能重現。

它還有第二個後果，比髒東西嚴重：**那個注入會讓 `docker save` 直接失敗**——也就是說**大約每六次建置就有一次，會產出一張根本匯不出去的映像**，而且以前沒有任何東西會告訴你，你只會看到匯出到一半爆掉。現在匯出前會先驗 `docker save`，這類問題當場擋下。

⚠ 一句話結論：**在這台機器上建交付映像，本質上是擲骰子**。修法已經進去了（清理寫在會被注入的那一層），但第 8 段真的重建全部映像時，如果哪張映像匯出失敗，**先重建一次再說，那不是你的設定壞了**。

**第二件要你裁的（Q38）**：codeserver 的**上游官方映像**裡，帶著一把相依套件的測試私鑰（`httpolyglot` 的測試夾具），asr 的 ubuntu 底層帶著安裝日誌。我們只能在上面「蓋掉」，**沒辦法真的刪掉**——掃描看起來乾淨，但 `docker save` 還是會把原始資料搬進氣隙。要真的清掉只有兩條路：換掉 base 映像，或把映像壓平（會丟掉分層與設定，要重做）。**我的建議是維持現狀**：那把鑰匙是公開 npm 套件裡人人下載得到的測試檔，不是我們的機密。細節在 `OWNER-QUESTIONS.md` Q38。
