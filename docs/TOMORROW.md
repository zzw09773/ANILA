## 五、你今天早上翻到的那個,查完了(2026-08-12)

**是我們的問題,而且是兩件。** ISO42001 那邊一行碼都不用改。

### ① 我們把記憶塞爆了對方,然後把它的拒絕訊息當成答案存起來

ANILA 會把你的長期記憶(偏好、已知事實、過往對話)組成一段,**放在最前面**送給 agent。
那段**沒有總量上限**,對方的上限是 **2000 字元**,一超過就整包擋掉。

🔴 **真正糟的是後面**:對方擋下來時是**回 HTTP 200**、把拒絕訊息當成正常回答吐回來。
所以那句「系統偵測到您的輸入內容疑似包含系統指令操作或攻擊樣式」
**被我們當成 AI 的回答存進資料庫、顯示在畫面上,還記了一筆用量**。

**你看到的是「AI 說我像攻擊者」,實際上是我們自己把它塞爆了。** 今天發生四次。
⚠ ANILA **結構上分辨不出來**——對方回 200、格式完全合法。

### ② 你的問題被截斷了

你問「陸海空軍懲罰法第 46 條的規定是什麼？」,對方**收到的是「陸海空軍懲罰法第」**,
斷在第一個空格——所以它才回「你沒指明條號」。

資料庫裡存的是**完整的**,所以**我們手上是完整的、送出去的是短的**。兩邊的日誌互相印證。
🔴 **但截斷發生在哪一行,我還沒找到,所以我沒有動它**——猜著改比不改危險。

### ③ 順帶發現

記憶萃取器**每一輪都失敗**,而且沒有任何地方會讓你或維運者知道。

### 🔴 這件要你決定(記成 Q50)

**ANILA 該不該把你的記憶送給「外部註冊的 agent」?**
那些端點的網址是**開發者自己填的**——等於使用者記憶離開平台,去到平台不控制的地方。
這次是院內自己的服務沒問題,但 Q49 才剛決定「未來同事的 agent 都要走平台」,**掛的人只會變多**。

我的建議是**最保守的那個**:記憶只在平台內部模型用,送外部 agent 時不附。
⚠ 但我**不建議**做成「每隻 agent 一個開關」——那又是一顆能從網頁動到的安全開關。
