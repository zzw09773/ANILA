中科院院內 AI 平台 · 給要把 agent 掛上平台的同仁

這份講「規矩與邊界」，不講「怎麼寫程式」。

實作步驟（範例程式、端點、旗標、註冊表單怎麼填）在治理中心的「開發者 → 開發指南」那一頁， 那裡是唯一的實作事實來源，會跟著平台版本走。

⚠ 請不要把那頁的內容抄到這裡——兩份平行維護的文件，三個月後一定會互相矛盾， 而讀的人不知道該信哪一份。這份只放不隨版本改變的規矩。

1三條規矩

規矩一：agent 內部要用模型，必須透過平台。

不要在你的 agent 裡直連模型端點。用平台發給你的憑證回頭呼叫平台。

為什麼：直連的話那些用量發生在平台外面，平台看不見也記不到， 沒有歸屬、沒有稽核。院內的計量與列管就是靠這條成立的。

規矩二：不要為了讓連線成功而關掉憑證驗證。

如果你的 agent 連平台時遇到憑證錯誤，正確做法是拿平台的 CA 給它， 不是加 verify=False。平台在註冊頁提供 CA 下載與驗證工具，就是為了讓你有正確的路可以走。

規矩三：你的 agent 是使用者資料的出口，請當它是。

使用者的問題會原樣送到你填的那個網址。那個網址指到哪裡，是你的責任。

2agent 上線的流程

  1. 在治理中心註冊你的 agent（填名稱與端點網址）
  2. 等管理員核准——核准前只有你自己看得到
  3. 核准後，其他同仁就能在對話裡選用，或由平台自動轉派

網址要完整，包含通訊協定。 填 172.16.x.x:8043 會被擋下來， 要填 http://172.16.x.x:8043。表單會告訴你，但很多人第一次都卡在這裡。

3憑證與連線

平台在 agent 註冊頁提供兩樣東西：

  • 平台 CA——讓你的 agent 信任平台的憑證
  • 驗證工具——讓你在自己的機器上先確認連得上、驗得過

先用驗證工具跑一次，再改你的程式。 連線問題有一半分不清是「憑證不對」還是「網路不通」，工具會直接告訴你是哪一種。

4你的 agent 會收到什麼、不會收到什麼

會收到不會收到
使用者這一輪的問題
這個對話裡的附件（使用者刻意附上的） 		🔴 使用者的長期記憶（偏好、平台歸納的事實、過往對話片段）

「不送記憶給外部註冊的 agent」是平台強制的，不是靠你自律。 判斷依據是「出向目標是不是註冊的 agent」這個結構事實—— 畫面上沒有任何開關可以改變它。

👉 所以如果你的 agent 需要脈絡，要自己管理，不要期待平台幫你帶。

5常見誤解

誤解實際
「我的 agent 會自動拿到使用者是誰、哪個單位」不會。要什麼脈絡請自己設計，並想清楚該不該拿
「平台會幫我重試」不會。你的端點沒回應就是失敗
「我回 200 就代表成功」⚠ 對呼叫你的人也是這樣。 如果你要表達「我拒絕這個請求」， 請不要用 200＋一段看起來像正常回答的文字——那會被當成答案存起來、顯示給使用者、還算進用量
「平台會擋掉不該問的東西」不要假設。你自己的邊界自己守
