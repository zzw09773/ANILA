1上線第一天：三件必做，順序不能錯

沒做完這三件，同仁插卡進來會卡住，而且畫面不會告訴他們該找誰。

  1. 建立單位（見第 2 節）—— 這是最容易漏的一件。 平台一裝好，單位是空的；新人插卡登入後會被要求「選擇所屬單位」， 而下拉選單裡一個選項都沒有，註冊就此卡住。
  2. 確認第一批管理員進得來（見第 3 節）。
  3. 確認模型可用（見第 4 節）——沒有可用模型，登入成功也問不出東西。

2單位

治理中心 → 單位（departments）。

單位是帳號的必填欄位：使用者完成註冊時一定要選一個。 所以單位必須先存在，順序不能反過來。

建議一開始就把單位建齊，而不是等人來申請再建。 一個新人卡在「沒有單位可選」的畫面時，他不會知道是平台還沒設定好， 只會覺得系統壞了——然後打電話給你。

3帳號與核准

使用者怎麼進來

  1. 插自然人憑證卡 → 平台驗章 → 建立一個待審帳號
  2. 使用者選擇所屬單位並送出
  3. 管理員核准 → 才能開始使用

「等待核准」對使用者是完全靜止的畫面。 他看不到排在第幾個、也收不到通知。 所以核准這件事要有人固定看，尤其是分批放行的那幾週。

權限

治理中心 → 使用者。可以調整角色與核准狀態。

4模型

治理中心 → 模型。這裡登記平台可以呼叫的模型端點。

「停用」現在真的等於「系統不會再用它」。 （2026-08-12 修正：先前背景服務仍會呼叫已停用的模型， 本機因為位址解不到才沒送出去——那是運氣，不是防護。現在解析階段就會排除它。）

「內部 / 外部」那個勾選框講的是網路可達性，不是信任等級。 它決定 proxy 追蹤畫面要不要顯示端點位址。⚠ 如果你為了連線因素改它， 請確認你知道自己在改什麼——這個欄位在匯入模型時也會被繼承。

5agent 的註冊與核准

同仁可以把自己寫的 agent 掛上平台。流程：他註冊 → 你核准 → 其他人才看得到。

核准 agent 之前請確認兩件事：

  1. 那個網址指到哪裡。 agent 的端點是註冊者自己填的， 平台會把使用者的問題送過去。
  2. 它有沒有透過平台呼叫模型。 院內規矩是 agent 內部要用模型必須經由平台 （這樣用量才有歸屬、才有稽核）。

✅ 使用者的長期記憶不會送給 agent——這是平台強制的，不是靠註冊者自律。

6院內規章知識庫

治理中心 → 知識庫。標記為可檢索的規章，會被使用者的提問自動查詢。

檔名取得好不好，比檔案內容重要——這句話對管理員更適用， 因為決定檔名的通常是你。掃描檔.pdf 上架之後就再也找不到了。

⚠ 純掃描的 PDF 內容不完整。上架前請確認它真的有文字層， 否則使用者會查不到你確定寫在裡面的東西。

7平台設定（只有 12 顆）

治理中心 → 平台設定。全部改完立刻生效，沒有「需要重啟」的項目。

設定頁刻意只有 12 顆。 2026-08-11 從 96 顆砍到 12 顆， 因為能從網頁動到的安全開關，就是一個等著被動的安全開關—— 那 84 顆被移除的參數正是兩個嚴重漏洞的根源。

要新增一顆設定前，先答這個問題：上線之後，誰、在什麼情境、為什麼不能等下一次改版？ 答不出來就不該是設定。

最常會動的那顆

院內規章的檢索門檻：太高會查不到、太低會撈到不相關的條文。 ⚠ 這個數字綁在當時使用的嵌入模型上，換模型就要重新量。

8用量與稽核

治理中心 → 用量 / 稽核紀錄。

目前的用量不是全貌。 使用者在畫面上聊天（串流）會被完整記錄； 但腳本、批次、第三方整合那種非串流呼叫目前不會記到用量。 ⚠ 所以「帳面上沒有」不等於「沒有人在用」。這是已知待補項。

9出事的時候

現象先看哪裡
全站打不開，但容器看起來都正常多半是前端代理指到舊位址。重載代理設定；服務重建之後一定要做這一步
使用者說登入不了①卡片與 PIN；②他是不是還沒被核准；③單位是不是還沒建
問答變慢或失敗治理中心 → 模型，看端點是否可達
使用者說「AI 說我像攻擊者」那可能是被呼叫的 agent 自己的拒絕訊息。看該對話的 agent 是哪一個
畫面一片空白網址打錯或舊書籤。目前不會顯示「找不到頁面」，請他從首頁重進

🔑 卡登壞掉、進不去平台的時候（破窗）

先確認你真的需要它。 這條路只給平台管理員（owner）， 而且只在卡片登入本身失效時使用——例如憑證鏈換過、CA 過期、讀卡元件掛掉。 一般的「某個人登不進來」不要用這條，那是核准或單位的問題（見第 3 節）。

做法：在登入頁網址後面加上參數：

https://<平台位址>/login?show_alternatives=1

那會讓平時隱藏起來的「其他登入方式」區塊出現，你就能用帳號密碼登入。

那個參數只是把畫面顯示出來，不是鑰匙。 知道網址的人並不會因此獲得任何權限——後端仍然只放行 owner 帳號，其他人填了帳密照樣進不去。 所以它不是祕密，但也不必主動公告：平時藏起來是為了讓三千位同仁不要走上一條他們用不了的路。

⚠ 平時那塊是刻意隱藏的。 如果你在沒有加參數的情況下看到它， 表示這台不是「卡登唯一入口」模式——那在內網正式部署上是不對的，請檢查設定。

code-server 的密碼等於平台的最高權限。 它掛載的是可寫的整包專案原始碼、未遮蔽的機密目錄，以及 Docker 控制通道。 那把密碼只能給平台管理員。
