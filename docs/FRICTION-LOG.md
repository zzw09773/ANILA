# 反直覺紀錄

操作 ANILA 時覺得「不該是這樣」的地方都記在這裡。這些是優化目標。
每一條寫：在哪裡、發生什麼、為什麼反直覺、建議怎麼改。修掉的標 ✅ 並寫 commit。

---

## 2026-09-30　演練機 .35 從零安裝與初始設定

### 安裝

**F-01　安裝目錄要先用 sudo 建，安裝程式不會說**
在哪：第一次安裝。
發生：`/opt/anila`、`/var/lib/anila` 不存在時，一般帳號跑 `anila-update.sh` 會在中途停下。
反直覺：一條指令裝好的承諾，第一步就得先知道要 sudo 建兩個目錄。
建議：✅ `preflight.sh` 會先檢查並印出 sudo 指令（9ee7452d）。安裝程式本身在動任何東西之前也該做同樣檢查。

**F-02　443 被佔用沒有安裝選項**
在哪：共用主機。
發生：只能事先手寫 `/opt/anila/state/.env` 加 `NGINX_HTTPS_PORT`。
反直覺：唯一要問的是站台名稱，但埠衝突也是第一次安裝就可能撞上的事。
建議：安裝程式偵測到 443 被佔用時直接問要用哪個埠。✅ 已由 `preflight.sh` 提示（9ee7452d）。

**F-03　密鑰印在畫面上**
在哪：第一次安裝。
發生：管理員與資料庫密碼印到標準輸出；用 nohup 或導到檔案時就留在日誌檔。
反直覺：「只顯示這一次」的東西，實際上會被任何 log 收走。
建議：只寫進 `generated-secrets.txt`（600），畫面只印檔案路徑。

**F-04　失敗的第一次安裝在 operations.log 記成 failure，重跑成功後沒有說明兩者關係**
在哪：第一次安裝失敗後重跑。
反直覺：看 log 會以為曾經壞過一版。
建議：重跑成功時註記「接續上次未完成的安裝」。

**F-05　`csp-credential-dirs` 在 `docker ps -a` 顯示 Exited**
在哪：安裝後檢查容器。
反直覺：看起來像服務掛了，其實是做完就結束的初始化。
建議：名稱或標籤標明是一次性工作；文件已註明（INSTALL.md）。

### 登入

**F-06　管理員帳密登入要兩個動作才看得到欄位**
在哪：`/login`。
發生：要在網址加 `?show_alternatives=1`，再點「其他登入方式」，帳號密碼欄位才出現。
反直覺：卡片壞掉時唯一的回頭路，藏在兩層後面，而且網址參數沒有任何畫面提示。
建議：保留隱藏（避免同仁誤用），但參數要有文件以外的線索，或只要一個動作。

**F-07　開發機與正式機的登入頁長得不一樣**
在哪：開發機 `https://127.0.0.1/login`。
發生：開發模式直接顯示帳密欄位，正式姿態要先點「其他登入方式」。
反直覺：在開發機練熟的步驟，到正式機不一樣。

**F-08　管理員登入後停在治理中心，治理中心沒有進 ANILA 的入口**
在哪：登入後落點。
發生：管理員、開發者、單位管理員落在治理中心；頁面上找不到去 `/anila/` 的連結。
反直覺：平台本體是 ANILA，管理員自己也要用，卻只能手打網址。
建議：所有人登入後進 ANILA；治理中心頂端放「前往 ANILA」。
✅ 已改：沒帶 `next` 時一律進 `/anila/`；治理中心頂端加「前往 ANILA」；單位管理員在 ANILA 也看得到治理中心入口（原本只給擁有者、管理員、開發者，改落點後單位管理員會回不去）。

### 初始設定

**F-09　私有 IP 的模型要兩道開關，錯誤訊息是英文**
在哪：註冊模型、外部服務。
發生：`.env` 的 `ANILA_ALLOW_PRIVATE_ENDPOINT=1` 已開，註冊仍被拒：「endpoint_url host '172.16.120.35' is a private (RFC 1918) IP. ANILA_ALLOW_PRIVATE_ENDPOINT must be on, and the host must be listed in the console trusted hosts.」要先到「信任主機」加 IP。
反直覺：內網的模型本來就全在私有 IP，這是每次安裝必經的一步，卻要從英文錯誤訊息倒推。訊息也沒說哪一道已經開了。
建議：訊息改中文、只講缺的那一道，並附「前往信任主機」連結；或在註冊模型的表單內直接加入信任主機。

**F-10　指定主路由前要先給全院授權，錯誤訊息沒說在哪裡給**
在哪：模型角色 → 主路由。
發生：「全院預設必須具有有效的全院授權」。角色頁的「授權給全院」只能對「已經擔任該角色」的模型用，而主路由正卡在還不能擔任，要改去模型的授權設定。
反直覺：先有雞還是先有蛋。指定主路由本來就意味著全院要能用。
建議：指定主路由時一併建立全院授權（寫稽核），或在錯誤訊息旁直接提供「授權給全院並指定」。

**F-11　改了語音位址，閘道一分鐘以上還在用舊位址；「探測」回傳成功但狀態是「未知」**
在哪：外部服務 → 語音。
發生：PUT 後按探測，畫面狀態仍是 unknown；asr-gateway 的 `/asr/health` 仍顯示舊的 `decode_url`。
反直覺：按了探測卻不知道結果，也不知道新設定何時生效。
建議：探測同步回報結果；存檔後通知閘道立即重讀，或畫面寫明「約 N 秒內生效」。

**F-12　API Key 與外部服務憑證只寫不讀，無法從另一套環境搬設定**
在哪：從開發機照抄設定到新環境。
發生：docling 的憑證在開發機讀不出來，要去模型主機的容器環境變數找。
反直覺：這是對的安全設計，但「照某台的設定再做一台」沒有路。
建議：提供設定匯出（不含密鑰、標出哪些要另外填）與匯入。

**F-13　儀表板「模型 1/1 健康」但模型頁寫「尚未註冊模型」**
在哪：全新安裝的儀表板。
發生：平台自己的 `anila-router` 入口被算成一個模型。
反直覺：兩頁對「有沒有模型」說法相反。
建議：儀表板不把平台入口算進模型數，或另列。

**F-14　`/api/health` 回 `200 text/html`**
在哪：安裝後用 curl 檢查。
發生：不存在的 API 路徑被前端接住，回首頁。
反直覺：看起來像健康檢查通過。
建議：`/api/*` 未命中時回 404 JSON。

**F-15　ANILA 裡的「治理中心」入口藏在「平台入口」彈窗裡**
在哪：ANILA 側欄。
發生：管理員要先點「平台入口」，彈窗裡才有「治理中心」。
反直覺：所有人登入後都先進 ANILA，管理員要回治理中心卻要多一層、名稱也看不出來。
建議：管理員身分時，側欄或頂端直接放「治理中心」。
