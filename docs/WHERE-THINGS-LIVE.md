# 東西放在哪裡 — 四層地圖

> 建立 2026-08-25，幕僚長。**用途：接手的人不必問「這個東西該放哪／去哪找」。**
> 🔴 **判準是內容，不是目錄名**——每一層的收容條件寫在下面，**不要照名字猜**。
> ⚠ 本檔描述的是**現況**（2026-08-25）。**其中「幾份」「幾行」這類數字會過期**，
> 每一層都附了**取得當下值的指令**，數字只用來讓你知道量級。

## 1️⃣ 團隊協作 — `~/anila-deliverables/`（**不在 repo 裡**）

**每天實際在用的那一層。** 多席位（幕僚長／審查長／Reviewer／資安官／實作席）共讀共寫。

| 檔 | 是什麼 |
|---|---|
| `IN-FLIGHT.md` | 🔴 **誰正在動哪些檔**。**開工前登記，不是事後補**——它是「唯讀不變式」的另一半：交回時逐位元組相同（①）只對「交回那一刻」說話，**②「擾動期間沒有別人在讀那棵樹」由這本登記簿回答**。 |
| `STANDING-RULES.md` | **累積的團隊規矩**。席位每重開一次，活在對話裡的制度就消失一次——**所以規則放檔案，不放訊息**。 |
| `queued-*.md` | **排隊中的派工單**（含不變式、驗收動作、SCOPE、硬限制）。 |
| `*-review-*.md` | **審查票**（收貨方出的，含實測輸出）。 |
| `RULING-*.md` | **裁定**（審查長或擁有者）。**裁定不是待辦，任何席位不得再就同一件事提案。** |
| `<作者>-*-report.md` | **交件報告**（grok／deepseek／doc 等）。 |

```bash
ls ~/anila-deliverables/queued-*.md | wc -l     # 排隊單數（2026-08-25：42）
wc -l ~/anila-deliverables/STANDING-RULES.md    # 規矩行數（2026-08-25：1428）
```

**收容條件**：**派工、審查、裁定、交件報告。**
🔴 **不收**：**未修補弱點的位置**（那一層在 §2）、**任何祕密值**。

## ✍️ 寫檔規則（不分層，每一條都有事故）

| 動作 | 規則 | 為什麼 |
|---|---|---|
| **寫任何檔之前** | 🔴 **先 `ls` 或 `git show HEAD:<path>` 看一眼** | **`cat >` 對既有檔是靜默截斷**。曾覆寫 `manual-checks.md`，**83 行沒了，其中包括「絕不對 live DB 跑 alembic」**——而 `git status` 上它只是一筆普通的 `M`。 |
| **heredoc** | **分隔符不得與內容可能出現的字串相同**（用 `ENDOFFILE`，不要用 `---`） | `---` 撞 markdown frontmatter → 後半段被 shell 當指令跑，`>` 開頭的引言變成重導向。 |
| **寫日期** | 🔴 **先 `date '+%Y-%m-%d'`**，不要用「我記得今天是」 | 跨日／resume 之後「今天」在對話裡看起來完全連續。**全隊曾一致寫錯一天**，最貴的是治理紀錄的接受日期。 |
| **寫數字** | **附上取得當下值的指令**；**數字要帶性質** | 「706」與「169」不是同一種數字（一個真 render、一個讀字串）。**沒帶性質的數字會自己長大。** |
| **寫宣稱** | **問「誰的動作會讓這句變假？他會不會回來改這裡？」** | 答案幾乎永遠是「不會」。**不釘會動的值**（SHA、數量、「最新」的檔名）。 |
| **祕密** | **永遠不寫值**；要比對就寫 `sha256` 前 8 碼 | 雜湊足以回答「是不是同一把、有沒有換過」，**而且可以安全寫進報告**。 |
| **印環境變數** | 🔴 **用固定寫法**，不要 `${v:+…}${v:-…}` | `${v:-default}` 在 `v` 非空時**回傳 `$v` 本身**——「只印存在性」的意圖照樣把值印出來。**同一天犯兩次。** |
| **掃祕密／掃檔** | 🔴 **用 `/usr/bin/grep`** | Bash 工具的 `grep` 是 ugrep shim，**預設跳過 gitignored（`.env`／`secrets/`／`*.pem`）與二進位**。 |
| **報命中數** | **附母集合大小與排除條件** | 「命中 0」與「排除 `node_modules` 後命中 0」是兩句話。**過濾條件要跟著數字走，不要留在指令裡。** |

## 📦 commit 規則

**🔴 前提：`commit` / `push` 只在擁有者要求時做。** 席位交件＝寫進工作樹，**不代表可以 commit**。

**commit 之前跑這三道**（缺一不可，都抓到過東西）：
```bash
git status --porcelain                      # ① 宣告母集合檢查：對照 IN-FLIGHT 的 SCOPE
                                            #    不在任何 SCOPE 內的檔 → 先歸屬，不要先驗
git status --porcelain | /usr/bin/grep -E '\.(orig|bak|rej)$|mutant|probe'   # ② 殘留掃描
git diff --cached | /usr/bin/grep -E '^\+' | /usr/bin/grep -nEi \
  '(BEGIN (RSA|EC|DSA|OPENSSH|PRIVATE) KEY|sk-[A-Za-z0-9]{20,}|ghp_[A-Za-z0-9]{20,}|AKIA[0-9A-Z]{16})'   # ③ 祕密掃描
```
⚠ **未追蹤檔要逐一過目再 `git add -A`**——曾有一份含祕密的 `.env` 工作副本躺在 repo 根、且不在 `.gitignore` 裡。

**訊息要寫成**：
- 🔴 **主旨一行**。多行主旨會被 git 併成一個很長的主旨。
- **寫「這給了什麼能力」，不要寫「修好了幾筆」**（例：「upsert 不再**能夠**弄壞既有向量」，不是「修好了 N 筆」）。
- 🔴 **`KNOWN, NOT FIXED` 要列**：**沒修＋記帳＝正確；沒修＋沒記＝缺陷。** 記的是**後果**不只是事實。
- **殘項要照抄**（例：「舊文件必須重匯，否則 embedder 掛掉時匯入仍會清掉既有向量」）。
- **互相承重的守衛不可分拆**要寫明（拆一半另一半會變恆真）。
- **結尾**：`Co-Authored-By:`。
- **push 前的祕密掃描要貼出實際命令**——**「我用了對的工具」是宣稱，貼出命令才是證據。**

## 🔀 合併規則（閘門順序）

```
作者交件 → 收貨方驗（🔴 驗收不自驗，寫的人不驗自己的產出）
        → 審查長關案 → 才合併 → 重建映像 → 活體確認
```

| 閘 | 規則 |
|---|---|
| **審查層級** | 紅線級雙票／一般功能單票／純文字幕僚長自驗（〈審查閘門分三級〉）。 |
| **合併前** | **各席確認手上沒有未落地的改動**；`git status` 與 IN-FLIGHT 對帳。 |
| **凍結窗** | 🔴 **全量突變檢查與「原樹當對照」的量測需要凍結**（harness 就地改檔，活樹撞它是結構性的）。凍結期間**全席停寫**，只有執行者能動。 |
| **DDL／alembic** | **審查長裁量**。界線寫**資料庫**不寫**埠**：正式庫🔴不准／同叢集 scratch 庫✅**准而且必要**（upgrade 與 downgrade 都要跑過、跑完自查殘留）／`.15`🔴完全不准。**沒跑過的 migration 是未驗產物。** |
| **合併後** | **逐一列出動到的服務再重建**（合併完≠部署完）。⚠ **`nginx` 是 bind-mount 單檔，要 `up -d --force-recreate`，不是 reload**。 |
| **驗新碼進映像** | 🔴 **跟原始碼（或 commit）比，不要跟另一個衍生物比**——「容器 vs tag 一致」在 build 沒發生時**必定綠**。用 `import` 取 `__file__`，不要寫死路徑（**本專案有兩種映像佈局**：csp 是 `COPY` 到 `/app`、worker 是 `pip install` 到 site-packages）。 |
| **活體確認** | **有些修法要重匯才生效**（圖片位置、圖說）。**「重匯」永遠是那個最容易被當成別人會做的動作**——寫進合併後的收尾清單。 |

## 📌 兩條跨層的規矩

1. **文件是備援，機制才是主線**——**撞到問題的人手上是一個錯誤訊息，他不會在那一刻去翻 runbook。**
   能讓失敗自己說出成因與解法的，優先於寫進文件。
2. **不要寫需要別人回來維護的話**——不釘會動的值（SHA、數量、「最新」的檔名），
   改寫成**取得當下值的指令**。本檔每一節的指令就是照這條寫的。
