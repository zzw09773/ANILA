# 東西放在哪裡 — 四層地圖

> 建立 2026-08-25，幕僚長。**用途：接手的人不必問「這個東西該放哪／去哪找」。**
> 🔴 **判準是內容，不是目錄名**——每一層的收容條件寫在下面，**不要照名字猜**。
> ⚠ 本檔描述的是**現況**（2026-08-25）。**其中「幾份」「幾行」這類數字會過期**，
> 每一層都附了**取得當下值的指令**，數字只用來讓你知道量級。

## 1️⃣ 團隊協作 — `~/anila-deliverables/`（**不在 repo 裡**）

**每天實際在用的那一層。** 多席位（幕僚長／審查長／Reviewer／資安官／實作席）共讀共寫。

| 檔 | 是什麼 |
|---|---|
| `IN-FLIGHT.md` | 🔴 **誰正在動哪些檔**。**開工前登記，不是事後補**——它是「唯讀不變式」的另一半：交回時逐位元組相同（①）只對「交回那一刻」說話，**②「擾動期間沒有別人在讀那棵樹」由這本登記簿回答**。 |
| `STANDING-RULES.md` | **累積的團隊規矩**。席位每重開一次，活在對話裡的制度就消失一次——**所以規則放檔案，不放訊息**。 |
| `queued-*.md` | **排隊中的派工單**（含不變式、驗收動作、SCOPE、硬限制）。 |
| `*-review-*.md` | **審查票**（收貨方出的，含實測輸出）。 |
| `RULING-*.md` | **裁定**（審查長或擁有者）。**裁定不是待辦，任何席位不得再就同一件事提案。** |
| `<作者>-*-report.md` | **交件報告**（grok／deepseek／doc 等）。 |

```bash
ls ~/anila-deliverables/queued-*.md | wc -l     # 排隊單數（2026-08-25：42）
wc -l ~/anila-deliverables/STANDING-RULES.md    # 規矩行數（2026-08-25：1428）
```

**收容條件**：**派工、審查、裁定、交件報告。**
🔴 **不收**：**未修補弱點的位置**（那一層在 §2）、**任何祕密值**。

## 2️⃣ 敏感稽核 — `~/anila-private-audits/`（**不在 repo 裡**）

**收容條件（判準是內容）**：**寫了「尚未修補的弱點在哪一行」的東西**、`.env` 快照、資料庫 dump。

⚠ **repo 在 2026-08-24 已轉為 private，而這一層仍然不進 repo**——
🔴 **理由換過**：從「任何人看得到」變成「**弱點清單不該跟著程式碼一起流通**」。
**理由換了要寫下來，否則下一個人會推論「現在 private 了所以可以搬進去」。**

**權限現況**：目錄與報告同組可讀；**含祕密的三個檔鎖到只有擁有者**（`.env` 兩份快照、DB dump）。
```bash
ls -ld ~/anila-private-audits                                   # 目錄權限
find ~/anila-private-audits -maxdepth 1 -type f -perm 600 -printf '%f\n'   # 鎖起來的是哪幾個
```

## 🔴 常見的放錯位置（都發生過）

| 想放的東西 | 該去哪 | 為什麼不是另一層 |
|---|---|---|
| 「這條弱點還沒修，位置在 X:123」 | **§2** | 放 §1 等於跟派工單一起流通 |
| 「這張單的驗收條件」 | **§1** | 放 §3 會讓 repo 變成工作板 |
| 「這條風險我們決定接受」 | **§3 PRE-TAG** | 🔴 **放 §1 排隊單裡＝沒有人會再讀到它**（排隊單不是給未來的人讀的地方） |
| 「這個 session 學到的規矩」 | **§1 STANDING-RULES** | 放對話裡＝席位重開就消失 |
| 祕密的值 | **哪一層都不行** | 只放 `.env`（不進追蹤）；報告裡用 `sha256` 前 8 碼代替 |

## 📌 兩條跨層的規矩

1. **文件是備援，機制才是主線**——**撞到問題的人手上是一個錯誤訊息，他不會在那一刻去翻 runbook。**
   能讓失敗自己說出成因與解法的，優先於寫進文件。
2. **不要寫需要別人回來維護的話**——不釘會動的值（SHA、數量、「最新」的檔名），
   改寫成**取得當下值的指令**。本檔每一節的指令就是照這條寫的。
