## 二、今天最重要的發現：**「測試通過」在這個專案裡不可信**

六輪驗收，**每一輪都找到「改一行讓功能整個死掉、而測試全綠」的地方**。這不是實作者不用心——
每一包的東西都真的做出來、真的量過。是測試本身看不到那些地方。

| 輪次 | 一行改動 | 測試結果 |
|---|---|---|
| 插話 R1 | 關掉佇列 | **16/16 全過**，bug 在瀏覽器裡原樣復現 |
| 插話 R2 | 刪掉這輪修正的本體那一行 | **442 全過**；改成永遠回空陣列 → **也是 442 全過** |
| 插話 R3 | 刪 `userStoppedRef` 的重置 | **426 全過**；而使用者會看到**完整的答案被標成「已停止」** |
| Triton R2 | `input_type` 兩條路由釘死 document | **1873 全過**，逐字相同 |
| Triton R3 | 長度前綴改成大端 `"<I"→">I"` | **1892 全過**；打活體 Triton **每一次呼叫都 INVALID_ARGUMENT** |

**共同根因有兩種形狀，記住它們：**

1. **測試根本沒碰到那一層。** 插話那三輪：全套 442 條裡**沒有一條掛載 `App` 或 `ChatRuntime`**，
   行為測試是拿自己捏的假依賴打一個 helper，主程式那側只靠 `readFileSync` + 正規表示式掃原始碼。
   **掃原始碼的不是測試。**
2. **測試的資料只有一筆，而檢查器寫得不會失敗。** Triton 那個位元組順序：
   所有斷言都只送**一段字串**，而測試自己的解碼器遇到亂長度會被切片夾住 → 單筆永遠原樣還原。
   **一個不會失敗的檢查不是檢查。** 送兩段就會解出亂碼。

## 三、插話資料遺失——三種做法，前兩種被否決

**症狀**：模型還在回答時，使用者插一則訊息，第一則回答**顯示完整但沒存進去**，重整就沒了。

**根因**（實測確認，不是推論）：插話那則**沒有帶父節點**，伺服器就去看「目前的葉節點」——
而第一則回答還沒存，葉節點還停在第一個問題上。於是插話掛到第一個問題底下，
第一則回答要存的時候撞到「同一父節點下的子訊息角色必須相同」。
**不是競態**（append 有鎖序列化），是父節點選擇規則本身的問題。

| 做法 | 結果 |
|---|---|
| ① 放寬角色檢查 | **算過就否決**：兩則會落在互斥分支，先存的那則還是會從畫面消失，只是不再報錯——**變成靜默失敗** |
| ② 客戶端排隊 | **兩輪、驗收兩次都沒過並廢棄**。只要內容還留在瀏覽器等，重整／關分頁／當掉／第二個分頁**每一條都會漏**。而且它把「掉模型的回答」換成「掉使用者已經被畫面收下的字」——更糟 |
| ③ **先存伺服器＋回覆佔位子** | 擁有者拍板，目前的做法。使用者按 Enter 的當下訊息就到伺服器，回覆的位子先佔起來，葉節點不會在半途移動 |

**做法③的兩輪重點：**
- 第二輪把「存訊息＋佔位子」合成**伺服器端一個交易**，而且**量出光靠資料庫列鎖不夠**——
  五次跑三次還是在根節點分岔（兩邊讀到同一個 NULL 葉節點）。改成**讀值比對再寫**
  （compare-and-swap），對不上就整個退回重試。**不依賴 `FOR UPDATE`，換資料庫也成立。**
  重量十次全乾淨。⚠ **PostgreSQL 上沒有量過**，程式註解裡有寫。
- 順帶抓到**使用者自己那則訊息的泡泡根本沒有顯示錯誤的地方**（只有回答那側有），
  所以先前那句假訊息（「沒有存進對話紀錄，請重新送出」——**而訊息其實已經在資料庫裡了**）
  是使用者唯一看得到的東西。照做就會送兩次。

🔴 **未關**：瀏覽器當掉／斷電仍會留下永遠寫不進去的空回答列，**全 repo 沒有任何回收機制**。
不是資料遺失（使用者文字在、畫面標示誠實、後續對話正常），但那格答案永遠空著。

## 四、CSP 直接講 Triton（四輪）

**為什麼要做**：內網那台 `172.16.120.35:9001` 的 embedding 模型**只開 gRPC**
（Triton 2.57.0，HTTP 埠 8000/8001/8002 實測都沒開）。平台只會講 OpenAI 那套 HTTP JSON。
擁有者裁定**做在 csp 裡，不另開容器**（氣隙環境少一張映像要搬）。

**我原本反對的理由是錯的**：我以為 csp 映像沒有編譯器裝不了 `grpcio`。
實測 `python:3.11-slim` 直接抓現成 wheel，18 MB，而且帶的 `protobuf 7.35.1` 跟 csp 現有的同版。

**必須記住的模型契約**（全部實打量出來）：
- `query` 張量一次**只能一段**字串；`documents` 可以一批
- 輸出 **4096 維**
- **同一句話走 query 和走 documents，cosine 只有 0.6–0.8**——兩側是不同的東西
- **弄錯不會報錯**，只是檢索悄悄變差

🔴 **擁有者自己的 embed proxy（`infra/models/src/embedding_proxy/app.py`）永遠送 `documents`**。
pydantic 預設忽略未知欄位，所以 `input_type` 送過去**既不報錯也不被讀**。
兩輪驗收獨立確認。已記進 `docs/FAKE-CONTROLS.md` #35，**沒有去改那支程式**——
那是另一套獨立建置的東西，這棵樹沒有任何測試碰得到它，**改了驗不了的東西正是這包在消滅的**。
**要用那條路的話，那支 shim 要接 `input_type`。**

**四輪各修了什麼**：R1 功能可用但旗標到不了容器、兩條既有測試被弄壞；
R2 補上但 `input_type` 接線被假測試守著；R3 換成真 gRPC 接縫的行為測試、
補上 runbook 漏掉的第四個前提；R4 補位元組順序覆蓋、修一條做不到的排錯指示。

**R4 的結果值得記**：那個位元組順序**本來就是對的**，`services/csp/app/` 底下**一行都沒改**——
問題純粹是「沒有東西釘住它」。修法全在測試：讓測試自己的解碼器**有能力失敗**
（宣告長度對不上剩餘位元組就拒絕）、加上位元組字面值斷言、
並把第二份寬鬆解碼器換成 import 同一支。突變下去 **12 條紅**，還原 **1917 過**。

R4 另外：`EMBEDDING_TIMEOUT` 接進 compose（新增 16 條 passthrough 測試釘住）、
兩個守衛各自獨立釘住（並加對照測試，讓「乾脆全部拒絕」這種偷懶修法過不了關）、
部署腳本對 `.env` 的「有沒有設」判斷改成跟 compose 一致（行首空白／tab／`export`／
引號／CRLF／行尾註解都測過，21 條測試跑腳本自己的函式）。
套件 **1938 過**（base 1892，+46 條），兩種 cwd 一致。

「ANILA_ENV 未設為 production — 正式模型 http fail-closed 守衛不會啟用」，
**那句話從 P0.2 之後就不成立了**。R3 才在它的姊妹腳本裡修掉同一句，這支還留著。超出範圍沒改。
