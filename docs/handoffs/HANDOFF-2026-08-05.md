### 數字

舊套件漏掉的那些，每一個都是真的會出事的：模型永遠看不到對話歷史、點側邊欄沒反應、
助理回答完全沒存進後端、存檔失敗不再標記泡泡、「停止產生」按了照樣跑完。

### 工具在哪

`apps/anila-shell/scripts/mutation-check.mjs`
- `node scripts/mutation-check.mjs` — 跑全部；**任何一個突變存活就 exit 1**
- `--check-anchors` — 只檢查錨點還對不對得上（快）
- `--list` / `--restore`

**⚠ csp 那邊還沒有同樣的東西。** Triton 那五輪證明同樣的盲區在後端也存在。

### 這套工具自己的四個陷阱（都是今天踩出來的）

1. **`--check-anchors` 全綠 ≠ 清單還對得上產品。** 它只證明字串還在。
   今天有一個突變守著一個**產品端零呼叫的死函式**——錨點檢查綠、既有測試照樣紅，
   **唯一徵兆是它在新測試那一組存活**。這是目前見過最安靜的假護欄。
2. **執行器本身會回報「假的抓到」。** 舊版在既有測試已經紅的情況下照樣繼續、
   把功勞算給它。現在沒有綠燈基準就拒絕測量。
3. **突變必須保留所有識別字。** 好的範例：`embedding_input_role="query"[:0] + "document"`
   ——字面上 `"query"` 還在原始碼裡，grep 型假測試看不見。
4. **假後端會跟產品漂開。** 這次在合併當下就發生（見第四節）。

### 那條「弱測試要自我標記」的規則

掃原始碼的測試不禁止，但**必須在檔頭標 `@source-text-guard`**，清冊要求精確一致——
所以新增一條弱測試必然在 diff 裡看得見。**規則明文禁止「刪掉那些測試讓它變綠」。**

第三批（插話＋測試地基）git 報**零衝突**——因為兩包動的是同一個檔案的**不同區塊**。
但插話把 `app.jsx` 改了 +556/−283，而測試地基的突變錨點是**那個檔案裡的字面字串**。
**四個錨點斷了，git 完全沒有理由知道。**

→ **合併完立刻 `--check-anchors`**，這已寫進下面的檢查清單。

### 28 條紅，而且是好的那一種

同一次合併，anila-shell 從各自全綠變成 **28 條紅**。
根因：插話把送出路徑改到**新端點** `POST /turn`，而測試地基的假後端只認得舊的 append 流程。

**這正是那份工作自己警告過的漂移，只是提早到合併當下發生——而且是大聲失敗，不是繼續全綠。**
25 條是假後端落後、4 條是注入點指著退休端點、3 條是**產品改對了而斷言釘著舊措辭**。
