# UX 想法累積 — 「不必要的難」

> 這份文件只記**不必要的難、不清楚、不歡迎**——不是功能許願單,也不是 bug tracker。
> **已在 `PLAN.md` 排程的項目不重報**;若踩到,只在當輪末尾註記 overlap。
> **壞掉(broken)**與**難用(confusing)**分開:前者屬 PLAN 缺陷,這裡最多一行指路。
> 寫法固定四欄:**時刻** / **誰受害×頻率** / **修法粗估** / **是否刻意**。
> 排序原則:(咬人頻率) × (修法便宜程度)——兩邊都高的放最上。

> 後續輪次請**往檔案底部追加**新的日期小節,不要改寫舊輪的判斷

### 立刻可做

#### 1. 登入頁自稱「治理中心」,三千人第一次刷卡卻以為走錯門
- **時刻**:一般使用者打開登入頁,大標是「ANILA 治理中心」,副標「知識治理控制台 · 請使用自然人憑證卡登入」;頁尾還寫「CSP 控制平面」。
- **誰受害×頻率**:全院第一次刷卡(~3000 人各一次)＋之後若書籤停在 `/login` 的每次回訪。頻率高。
- **修法粗估**:文案改寫(依 `?next=` 或預設落地切「ANILA」／「治理中心」兩套標題即可)。不需 schema。
- **是否刻意**:多半是 CSP Vue 登入頁兼作全站入口後,標題沒跟觀眾分開。安全無關。

#### 2. 「分享」畫面上的「可存取對象」是假的——選「指定人」仍產出任何人有連結就能讀的 token
- **時刻**:使用者點分享 → 看到「組織內 / 同部門 / 指定人」三鈕 → 按「產生連結」拿到 URL。實際 `createShare` 只送 `mode` / `allowFork` / `expiresAt`;後端 `ShareCreate` 無 scope 欄;`GET /api/public/share/{token}` 註明 **No auth required**。說明還寫「分享紀錄會寫入 CSP audit log」(對一般人是黑話)。
- **誰受害×頻率**:每次想「只給某同事看」的分享。使用者以為鎖了對象,其實是匿名連結。
- **修法粗估**:**立刻**——拿掉或停用那三顆假按鈕,改成誠實文案「任何拿到連結的人(在連結有效期內)都能讀」。P4.3 真正改指定人時再換 UI。
- **是否刻意**:不像刻意政策,像後端還沒跟上的半成品 UI。與 PLAN P4.3 **overlap**(P4.3 做完這條消失;在那之前假 UI 每天在騙人)。

#### 3. 聊天空狀態與組字列把內部機制當產品語言
- **時刻**:進 ANILA 空白對話看到「Router 會自動分派；也可用 @agent 直接指定」;用 `@` 點了 agent 後組字列出現「直接指定 (bypass router)」;交接選單標題是「HANDOFF 交接」。
- **誰受害×頻率**:幾乎每次新對話、每次 @ 提及。一般使用者(~3000)每天。
- **修法粗估**:文案置換——例如「ANILA 會幫你找合適的助手;也可以用 @名稱 直接指定」「已指定助手」「交給其他助手 / 交給同事」。不動邏輯。
- **是否刻意**:偏開發者美學殘留。Router / bypass / handoff 是實作詞,不是使用者詞。

#### 4. `docker compose up -d` 重建 csp 之後,全站 502,容器卻顯示 healthy
- **時刻**:維運者 recreate `csp`(套 `.env` / image),`docker ps` 全綠;使用者與自己打開 `/login`、`/api/health` 卻 nginx **502**。本輪實測:nginx error log 連向舊 IP `172.21.0.3:8000`(Connection refused),而當下 `csp` 已在 `172.21.0.4`;檔案頂部註解已說明「upstream 在載入時解析一次會釘死 IP」,且 codeserver/n8n/anilalm/gitlab **已**改成 `$變數 + resolver`,但 `csp_backend` / `router_backend` / `anila_ui_static` / `anila_studio_backend` 仍是 `upstream { server 名:port }`。
- **誰受害×頻率**:一人維運,每次動 csp/router/ui/studio 的 recreate——開發期極常,上線後發版也會中。外觀像「平台掛了」。
- **修法粗估**:把上述四個 upstream 改成與 codeserver 同一套 variable `proxy_pass`(檔內已有範本)。可能要取捨 keepalive;屬 nginx 設定,不必動業務碼。
- **是否刻意**:歷史取捨(upstream keepalive vs 每次重解析)。註解作者知道這坑,卻只修了部分服務。

#### 5. Agent「測試連線」把「不是 401」都當成契約接對了
- **時刻**:開發者註冊 agent → 接派工 JWT 驗簽 → 按「測試連線」(P2.1 後不再核發 `csk-`)。後端若仍用寬鬆的 `accepted = resp.status_code != 401`,端點回 **404/405/500**(路徑錯、還沒實作 `/v1/chat/completions`)仍可能顯示「端點接受了」。模型健康探測同樣只要 `/health`、`/v1/models`、**或 `/`** 任一 `<500` 就算 healthy——根路徑常是任意網頁 200。
- **誰受害×頻率**:每個新掛上的 agent/模型至少一次;之後排錯時會反覆踩。開發者少數但每次都卡很久。
- **修法粗估**:收緊成功條件(例如僅接受預期的 4xx「缺訊息」或明確契約碼);健康探測拿掉「`/` 也算」、或要求至少命中 `/v1/models` 或 `/health`。小邏輯改＋測試。
- **是否刻意**:故意放寬以便「先證明網路通」;副作用是假綠燈。與「連線測試對會 404 的 URL 也過」同類。

#### 6. 列管對話的「禁止複製/分享」只有灰掉,不說是哪一級、為什麼、下一步是什麼
- **時刻**:使用者點複製 → tooltip「列管對話禁止複製」;分享鈕 disabled「列管對話不可分享」。不知道是營業秘密(可分享但稽核)還是密/機密(不可),也不知道能不能請誰處理。
- **誰受害×頻率**:凡碰到列管 agent 或升密對話的人;上線後會變常態。
- **修法粗估**:tooltip/禁用說明帶上實際等級＋一句「密與機密不可複製或分享;此狀態無法自行解除」。標籤級。
- **是否刻意**:外流閘門本身是規格;沉默是省略,不是政策。

#### 7. 第一次刷卡「等待核准」沒有可找的人
- **時刻**:卡登完成選單位後,畫面「一旦管理員核准,下次刷卡即可登入」——沒有單位窗口、信箱、或「找誰」。單位清單若空,只說「請通知管理員到 admin 介面建立 departments」。
- **誰受害×頻率**:每個尚未核准的新帳(上線週會爆量)。
- **修法粗估**:登入頁讀一條可設定的聯絡文案(公告橫幅或 env);或顯示「請洽貴單位窗口 / 平台管理員」。不必新角色系統。
- **是否刻意**:核准閘是規格(SYSTEM-MAP);缺聯絡資訊是疏漏。

### 值得做但要設計

#### A. Agent 上架要過「連線 → 軌跡測試 → admin 核准」,開發者自己做不完
- **時刻**:註冊精靈寫「待管理員審查」;列上「核准」鈕對非 admin 不可用,且必須先過「軌跡測試」(檢查 span 回報)。開發指南步驟仍偏長(MLSteam Lab、真實 URL 非 docker 名、`http://` 不可填 https、port forward、接 JWKS 驗簽／佈 CA…)。任一步失敗多半是英文例外或 SSL `WRONG_VERSION_NUMBER`。
- **誰受害×頻率**:每個想掛 agent 的所級開發者;上線前後會密集出現。太難 → 沒人掛 → router 沒東西可派。
- **修法粗估**:產品決策——軌跡關是否改成「警告可略過、admin 仍可看報告」、或讓 owner 自助跑通前兩關只留 admin 最終放行;精靈內嵌「http/https、信任主機、缺 `/health`、CA／JWKS」檢查清單。屬流程設計,不是改一行字。
- **是否刻意**:是。多關卡為上線前安全與可觀測性而加。與擁有者「不要越用越嚴格、開發者不會想掛 agent」的指令直接衝突——值得重新量一次「擋誰 / 自救 / 會不會擋到自己」。

#### B. 一般使用者的用量仍塞在 CSP,ANILA 裡看不到
- **時刻**:SYSTEM-MAP §1 寫「一般使用者的用量應該直接放進 ANILA」;現況用量頁在治理 UI,一般角色側欄還看得到「API 金鑰 / 模型 / 用量」。使用者若登入後停在 443 治理面,會以為要管模型。
- **誰受害×頻率**:想查自己用了多少的人(規格預期是多數);誤闖治理面的人。
- **修法粗估**:ANILA 設定頁加「我的用量」只讀圖;治理側欄對純 user 收斂到用量(+必要的金鑰若仍要)。需資訊架構,不是單一文案。
- **是否刻意**:遷移未完成;規格已寫方向。

#### C. 「交給同事」交接看起來能用,送出卻沒帶對方是誰
- **時刻**:交接選單 →「給同事」→ 輸入帳號 →「送出交接請求」。呼叫端只傳 `conversationId` 與 `note`,**沒有 `toUserId`**;後端 API 需要 `to_user_id`。
- **誰受害×頻率**:任何想把對話交給同事的人。
- **修法粗估**:這是**缺陷**,不是體驗打磨——應進 PLAN/缺陷列(接上使用者搜尋 + 傳 `to_user_id`,或暫時隱藏「給同事」)。此處只記「UI 說能做、後端沒接好」的形態,避免再長出第二個假控制項。
- **是否刻意**:半成品。與分享假 scope 同族。

### 觀察到但建議不動

#### i. 整批帶入的模型預設停用待複核
- 開發者會多按一次「啟用」,但猜錯 context/能力比誤上線更貴。P4.6 已明示;保留。

#### ii. 浮水印與列管外流閘(可做≤營業秘密、落稽核≥營業秘密)
- 摩擦是規格的嚇阻與稽核,不是無意義嚴格。說明文案可好一點(見立刻可做 #6),閘本身別動。

#### iii. 端點位址僅 owner／受權 dev 可改、回應面遮蔽
- 剛因「擋到自己」放過一輪;繼續加出口前先問值不值得(PLAN 開頭三問)。本輪不建議再收。

#### iv. 卡登偵測成功後顯示員工編號 / card SN
- 略裸,但有助確認「是我的卡」。建議維持;若要藏 SN 屬隱私微調,非痛點。

#### v. Reasoning / routing 折疊摘要
- 成功時是加分;失敗時把內部思考當答案——屬串流錯誤呈現,已在 PLAN「串流中途失敗要看得見」範圍,此處不另開體驗票。
