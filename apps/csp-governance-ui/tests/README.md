# 治理中心測試 — 這裡驗什麼、不驗什麼

> 🔴 **`npm test` 綠＝文字檢查通過，不等於程式跑得起來。**

## 為什麼要寫這句

這個目錄的測試，多數把 `.vue` 檔**當文字讀**（`read` 原始碼做字串/結構斷言），
而非把它 `mount`／`render` 起來跑。它們看起來就像在測那個元件，**而且綠了會讓人以為
那個元件真的被執行過——差別看不出來，除非寫在這裡**。

| 檢查 | 抓到 | 抓不到 |
|---|---|---|
| `vite build` | SFC 編譯、（template **語法**） | 任何要「跑起來」才會出現的錯誤 |
| `npm test`（文字式） | 字串/結構/契約面 | `setup()` 的 null deref、template 運算式求值、元件 mount 失敗… |

一個渲染期才會炸的元件（例如 `setup()` 裡解參照 `undefined`），**上面兩道都會綠**。

📌 數字是快照、會過期（盤點日 2026-08-22 的盤查：`src/` 下 51 個 `.vue`＝26 views＋24 components，
0 個被自動化檢查執行過）。**以當下實測為準，別照抄數字。** 此為具名的已接受風險，
見 `docs/archive/PRE-TAG-RESIDUALS-2026-08-15.md`「已接受風險」節（2026-08-22 審查長裁定）。

對照：`apps/anila-shell` 的測試套件**有** jsdom 真 render 覆蓋——**這兩個前端的「測試綠」不是同一種證據**。
