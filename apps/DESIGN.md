# ANILA 工作臺設計計畫

方法：frontend-design + frontend-patterns。這不是新皮膚，是把三個 Vite 應用收成**一個產品**。權威色、字、殼以本檔為準；各 app 只做對應，不另起色盤。

架構仍以 `PLAN.md` / `SYSTEM-MAP.md` 為準：三個網站、一次登入、一般使用者落到 ANILA。本檔只管畫面怎麼讀。文案名稱跟 編：工作臺、製作、系統管理。

## 0. 為什麼有這個產品

ANILA 要**取代**院內 Open WebUI。Open WebUI 是聊天遊樂場（對話清單＋模型下拉）。若一般使用者第一眼看到的是聊天室、模型選擇器或管理後台，取代就失敗。

近程工作是**行政與營運**：人事、採購、總務規範（RAG）、用文字或語音立刻得到指引、把結果做成可帶走的文件。

因此：

- 前門是 **ANILA 工作臺**（對話視窗＋專案入口）。我的知識庫／製作只在 ANILALM。
- 聊天是手段。出處、下一步比漂亮氣泡重要。
- 系統管理留在帳號選單。一般畫面不用「治理」或「中心」。

## 1. 色（具名 token，單一來源 `apps/shared/tokens.css`）

淺色預設。禁止近黑、霓虹綠、奶油底＋赤陶、軍綠、紫 `#7C4DFF`、圖表第二色用褐金。

| 名 | Hex | 用途 |
|---|---|---|
| `ink` | `#1B3A6B` | 品牌、頁標題、主按鈕、3px 院線 |
| `signal` | `#1A5BB8` | 連結、選取、焦點、圖表主色 |
| `canvas` | `#F2F5F9` | 頁底（冷灰藍，不是奶油） |
| `paper` | `#FFFFFF` | 卡、表、輸入 |
| `mute` | `#5A6B7C` | 次要字／圖示 |
| `hairline` | `#D7E0EA` | 細線 |
| `steady` | `#1F7A5C` | 只給健康／在線。不要霓虹綠 |
| `signal-40` | `#9BB8DC` | 圖表第二色（signal 的 40%） |

破壞性動作用 `danger` `#B03636`，從屬，不上導覽。圓角 6–8px，不要 16px 聊天泡。深色若以後要做，仍是 ink／canvas，不要紫黑。

## 2. 字

- **Wordmark**：ANILA Latin sans 600。鎖頭只有一個：`ANILA · 院內 AI 工作平台`。不要寫 ANILA LM。
- **標題**：Noto Sans TC 600。
- **內文**：Noto Sans TC 400。
- **時間／ID**：tabular／等寬數字。其他地方不用等寬。
- 工作臺殼上不出現 ROLE、SCOPE、DATA PLANE、build dev。

內網 CSP 不能載 webfont。堆疊把 Noto Sans TC 放前面，系統有就用，沒有再落到微軟正黑／PingFang TC。

## 3. 兩個佈局，一條頂欄

任何埠都是同一張桌子。共用頂欄：院線標記 ＋ 鎖頭 ＋ 帳號。

```
工作臺（一般落地）
┌──────────────────────────────────────────┐
│ ANILA · 院內 AI 工作平台          帳號 ▾ │
├────────┬─────────────────────────────────┤
│ 工作臺 │   對話視窗                       │
│ 專案   │   輸入＝院線卡                    │
└────────┴─────────────────────────────────┘

系統管理（admin／dev，從帳號選單進去）
┌──────────────────────────────────────────┐
│ ANILA · 院內 AI 工作平台          帳號 ▾ │
├────────┬─────────────────────────────────┤
│ 人     │  KPI 卡 ＋ 表                    │
│ 用量   │  第一顆 KPI 左側 ink 條          │
│ 平台   │                                 │
└────────┴─────────────────────────────────┘
```

規則：

- ANILA 左側：工作臺／專案入口。我的知識庫與製作只在 ANILALM，可用帳號選單一條 outbound 打開。
- 系統管理只在帳號選單。一般側欄沒有這一列。
- 系統管理側欄分組是「人、用量、平台」，不要裝飾用 01／02／03。
- 沒有 ROLE／SCOPE／PATH 狀態列。版本寫在帳號選單。
- 工作臺不要月亮／太陽／禮物工具列。
- URL、左側／頂部高亮、主畫面必須是同一頁。

## 4. 簽名：院線卡

白紙、頂 3px ink、1px 冷色 hairline、圓角 8。用在登入、KPI、空狀態、入口卡、輸入、表框。那條頂線就是簽名。不要把菱形 logo 當主視覺。

自然人憑證卡登入是前門。登入頁只有這一張主卡；帳密收在「其他登入方式」。

## 5. 文案（編）

| 做 | 進行中 | 完成 |
|---|---|---|
| 登入 | 驗證中 | 已登入 |
| 製作 | 製作中 | 已製作 |
| 登出 | 登出中 | 回到登入頁 |
| 上傳 | 上傳中 | 已上傳 |

- 落地／側欄第一項：工作臺
- 做事：製作（產出＝帶走的成品，不是站名。不要鑄造）
- 管理：系統管理
- 空幫手：還沒有可用的幫手／目前沒有可請的幫手。需要的話，請聯絡系統管理員。
- 功能好了：只寫名字。未就緒：隱藏該列。死門才說「尚未開放」。不要掛還沒好的徽章。

## 6. 元件模式

- 殼／導覽／頁頭：**組合**，不繼承。ANILA 與 ANILALM 各自一份導覽。
- 表格動作：主動作一顆，其餘 `⋯` overflow。
- 空狀態：標題 + 下一步 + 可選動作，包在院線卡裡。
- 鍵盤 `:focus-visible` 用 `signal`。尊重 `prefers-reduced-motion`。

## 7. 不做

不弱化卡登／PKI。不合併本 PR。不把系統管理做成一般使用者前門。不新開色盤。
