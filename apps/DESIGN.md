# ANILA 工作臺設計計畫

方法：frontend-design + frontend-patterns。這不是新皮膚，是把三個 Vite 應用收成**一個產品**。權威色與入口以本檔為準；各 app 的 token 檔只做對應，不另起色盤。

架構仍以 `PLAN.md` / `SYSTEM-MAP.md` 為準：三個網站、一次登入、一般使用者落到 ANILA。本檔只管畫面怎麼讀。

## 0. 為什麼有這個產品

ANILA 要**取代**院內 Open WebUI。Open WebUI 是聊天遊樂場（對話清單＋模型下拉）。若一般使用者第一眼看到的是聊天室、模型選擇器或管理後台，取代就失敗。

近程工作是**行政與營運**：人事、採購、總務規範（RAG）、用文字或語音立刻得到指引、把結果做成可帶走的文件。國防決策／數位孿生是以後的故事，現在不加迷彩、兵棋或行銷對照。

因此：

- 前門是**工作臺**（工作臺／知識庫／製作／專案入口），不是對話清單。
- 聊天是手段。出處、下一步比漂亮氣泡重要。
- 總務／人事／採購同仁要看得懂第一屏，不必知道 agent 或 DATA PLANE。
- 系統管理留在後臺。一般畫面不用「治理」或「中心」。視覺是官方藍工作臺。

## 1. 色（六顆具名 token）

淺色優先、官方藍。禁止三套 AI 預設臉：奶油底＋赤陶襯線、碳黑＋酸綠終端、報紙細線。

| 名 | Hex | 用途 |
|---|---|---|
| `ink` | `#1B2230` | 主字 |
| `paper` | `#F7F8FA` | 頁底 |
| `card` | `#FFFFFF` | 卡面 |
| `line` | `#DFE3EA` | 邊線 |
| `official` | `#2B4C7E` | 行動／焦點／品牌 |
| `danger` | `#B03636` | 破壞性動作 |

深色只是同一六顆的柔和藍灰對應，不是第二套產品。狀態色（成功／警告）從屬，不上主導航。

## 2. 字

- **標題**：系統 sans，字重 600，略收字距。不是等寬、不是襯線。
- **內文／導覽／標籤**：同一套 sans。標籤不做大寫、不做等寬。
- **數字／ID／時間**：`font-variant-numeric: tabular-nums`；只有識別碼與程式碼才用等寬。

內網 CSP 不能載 webfont。堆疊：Segoe UI / 微軟正黑 / PingFang TC / Noto Sans CJK TC。

## 3. 資訊架構（同一殼）

一般使用者永遠看到四個入口。系統管理不是第四個產品，是進階面。

```
一般使用者工作臺
┌──────────────────────────────────────────┐
│ ANILA                    帳號  淺色  登出 │
│ 工作臺  我的知識庫  製作  專案入口         │
├──────────────────────────────────────────┤
│                                          │
│   早安，開始今天的工作                    │
│   查規範、問流程、把結果做成文件          │
│   [工作臺] [我的知識庫]                   │
│   [製作]   [專案入口]                     │
│                                          │
└──────────────────────────────────────────┘

系統管理（owner / admin / developer）
┌──────┬───────────────────────────────────┐
│概況  │  ANILA · 系統管理                  │
│開發  │                                   │
│身分  │  主畫面＝目前 URL 的那一頁         │
│營運  │                                   │
│合規  │                                   │
│服務  │                                   │
│──────│                                   │
│工作臺                                    │
└──────┴───────────────────────────────────┘
```

規則：URL、左側／頂部高亮、主畫面必須是同一頁。`router-view` 用 `fullPath` 當 key，不留 keep-alive 殘頁。重整後角色不得漂移。

## 4. 簽名（只用一次）

**自然人憑證卡登入是前門。** 登入頁只有這一張主卡；帳密收在「其他登入方式」。不在工作臺再放開機動畫、終端提示符、Tweaks、ROLE／SCOPE。

Chanel：拿掉多餘配件。本輪拿掉的是「標籤大寫＋等寬導覽」與模型表七顆直向按鈕。分類浮水印已存在，不再另發明第二個簽名。

## 5. 文案

用使用者在做的事命名，不用系統內部名。

| 做 | 進行中 | 完成 |
|---|---|---|
| 登入 | 驗證中 | 已登入 |
| 製作 | 製作中 | 已製作 |
| 登出 | 登出中 | 回到登入頁 |
| 上傳 | 上傳中 | 已上傳 |

空狀態與錯誤必須寫下一步。禁止一般畫面出現 ROLE、SCOPE、DATA PLANE、Tweaks、fixture 位址。

## 6. 元件模式

- 殼／導覽／頁頭：**組合**，不繼承。四入口資料只有一份語意（工作臺／我的知識庫／製作／專案入口）。未就緒的列隱藏；死門才說「尚未開放」。
- 表格動作：主動作一顆，其餘 `⋯` overflow。動作欄不換行、不直向堆疊。
- 表單：送出前驗證，錯誤寫在該欄旁邊。
- 空狀態：標題 + 下一步 + 可選動作（compound）。

## 7. 品質下限

鍵盤 `:focus-visible` 用 `official`。尊重 `prefers-reduced-motion`。正文對 `paper` 對比至少 AA。管理表格可橫向捲，小螢幕不把動作欄折成錯列。

## 8. 不做

不弱化卡登／PKI。不合併本 PR。不把治理中心做成一般使用者前門。不新開色盤。
